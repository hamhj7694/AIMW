# DESIGN-GOVERNANCE — 디자인 거버넌스 (구)

> 저장소에 포함되지 않는 로컬 캡처 자료를 근거로 했으며, 이 문서는 경로에 의존하지 않는다.

작성일: 2026-11-22  
범위: 디자인 규칙의 우선순위, 문서 소유권, 결정 게이트, 변경 흐름, 구현 전 점검, 거부 패턴 기록.  
전제: 모든 규칙의 채택 분류는 `UI·UX 패턴 참고 후 자체 구현`이며 직접 코드·마크업·스크린샷 재사용은 0건이다.

---

## 1. 목적·적용 범위

| 항목 | 내용 |
|---|---|
| 목적 | 관찰 결과가 자체 설계로 넘어가는 과정에서 근거 품질과 토큰 일관성을 유지한다 |
| 적용 대상 | 10개 독립 라우트와 모든 공유 컴포넌트, 화면 명세, 양산 모드 명세 |
| 비적용 대상 | 제외된 레퍼런스 관찰, 확인 필요 상태로 보류된 규칙 |
| 판단 기준 | 규칙 우선순위와 결정 게이트를 통과한 항목만 구현 승인 |

---

## 2. 규칙 우선순위

충돌 시 아래 순서로 판단하고, 하위 단계가 상위 단계를 뒤집지 못한다.

| 순위 | 근거 단계 | 권한 | 충돌 시 처리 |
|---|---|---|---|
| 1 | 공식 플랫폼·디자인 시스템 가이드 | 최종 판단 근거 | 그대로 따르고 예외는 기록 |
| 2 | 검증된 레퍼런스 관찰 | 설계 보조 근거 | 1단계에 양보, 패턴만 참고 |
| 3 | 자체 디자인 결정 | 구현 세부 판단 | 1, 2단계 범위 안에서만 적용 |

관찰이 부분적이거나 오염 가능성이 있으면 2단계로 올리지 않고 `확인 필요`로 보류한다.

---

## 3. 문서 소유권

문서 이름은 역할로만 표기하며 **캡처 자산의** 구체 경로·파일명·링크는 적지 않는다.

| 문서 역할 | 소유 관점 | 변경 권한 | 연계 게이트 |
|---|---|---|---|
| 출처 신뢰도 평가 문서 | 출처 적합성, 제외 사유 | 출처 검토 담당 | G0 |
| 자료 목록 문서 | 자료 역할, 중복, 오귀속 | 출처 검토 담당 | G0 |
| 기능 대조 문서 | 서비스별 기능·채택 분류 | 기획 담당 | G0, G1 |
| 구성 대조 문서 | 토큰 대조, 점수·순위 보호 | 기획 담당 | G1 |
| 본 규칙 문서 | 규칙 ID, 근거 서술, 매핑 | 디자인 담당 | G1 |
| 토큰·정보구조 명세 문서 | 토큰명, 라우트, 상태 | 디자인 담당 | G1, G2 |
| 화면 명세 문서 | 화면·상태·반응형 표현 | 디자인 담당 | G2 |
| 양산 모드 명세 문서 | 모드별 게이트, 명시적 연결 | 디자인 담당 | G2 |
| 컴포넌트 명세 문서 | 컴포넌트 이름·속성 | 구현 담당 | G2, G3 |
| 의사결정 기록부 | 결정, 대안, 거부 사유 | 전 담당자 공동 | G4 |
| 본 거버넌스 문서 | 게이트, 흐름, 점검 항목 | 디자인 담당 | 전 게이트 |

단일 문서의 단독 변경은 허용하되, 토큰·화면·컴포넌트 세 문서 중 하나가 바뀌면 나머지 두 문서의 일치 여부를 반드시 확인한다.

## 4. 결정 게이트

| 게이트 | 통과 조건 | 필요 산출물 | 거부 시 조치 |
|---|---|---|---|
| G0 출처 적합성 | 오염·오귀속·이미지 의존 근거가 제외되었는가 | 근거 서술과 제외 사유 | 근거 교체 또는 `확인 필요` 보류 |
| G1 설계 일치 | 규칙이 토큰·정보구조와 1대1로 매핑되는가 | 매핑 표, 토큰 환산 내역 | 서비스 원본 수치 제거 후 재심의 |
| G2 구현 준비 | 접근성·반응형·상태·모드 게이트가 반영되었는가 | 화면 명세, 양산 모드 명세 | 관련 규칙 보강 후 재심의 |
| G3 구현 확인 | 이름 없는 컨트롤 0개, 가로 스크롤 없음, 상태 4종 유지 | 점검 결과, 예외 기록 | 결함 수정 후 재점검 |
| G4 변경 기록 | 결정·대안·거부 사유가 의사결정 기록부에 남았는가 | 새 결정 항목 | 기록 보완 전 변경 반영 금지 |
| G5 보호 대상 | 점수·순위·라이선스 메모가 바뀌지 않았는가 | 변경 대조 결과 | 변경 되돌림 후 재심의 |

`확인 필요` 상태인 규칙은 G1에서 승인하지 않고 G0로 되돌린다.

## 5. 변경 흐름

```text
[관찰 결과]
     |
     v
[규칙 초안] -- G0 출처 적합성 --> [근거 등록] -- 부적합 --> [보류 또는 폐기]
     |
     v
[설계 반영] -- G1 설계 일치 --> [토큰 매핑 확정]
     |
     v
[구현 전 점검] -- G2 구현 준비 --> [구현 착수]
     |
     v
[구현 후 확인] -- G3 구현 확인 --> [반영 완료]
     |
     v
[변경 요청] -- G4 변경 기록 --> [의사결정 기록] -- G5 보호 대상 --> [완료]
```

흐름은 되돌릴 수 있다. 게이트 미통과 시 다음 단계로 넘어가지 않고 이전 단계로 회귀한다.

## 6. 구현 전 체크리스트

- [ ] 채택 분류가 `UI·UX 패턴 참고 후 자체 구현`으로 명시되어 있다.
- [ ] 직접 코드·마크업·스크린샷 재사용이 0건임을 확인했다.
- [ ] 근거가 일반 서술로 적혀 있고 구체 경로·파일명·링크·주소가 없다.
- [ ] 이미지를 보았다는 표현이나 시각 스타일 단정이 없다.
- [ ] 약한 근거에 `확인 필요`가 표시되어 있다.
- [ ] 규칙 ID가 `UXR-<서비스코드>-<세자리 번호>` 형식이다.
- [ ] 서비스 원본 수치가 자체 토큰으로 환산되었다.
- [ ] 화면 폭이 앱 그리드·콘텐츠 최대폭·거터 세 토큰으로만 결정된다.
- [ ] 이름 없는 컨트롤이 0개이고 이미지 대체 텍스트가 유지된다.
- [ ] 메인·내비게이션·배너·푸터 랜드마크가 각 하나씩이다.
- [ ] 좁은 폭에서 가로 스크롤이 없다.
- [ ] 비동기 상태가 대기·진행·완료·실패 네 종류로 제한된다.
- [ ] 예측·세그먼트 수치에 신뢰도 라벨이 함께 붙는다.
- [ ] 서드파티 실패가 핵심 콘텐츠와 격리된다.
- [ ] 외부 추적 실패를 노이즈로 분류했다.
- [ ] 모듈이 기본적으로 독립이며 명시적 사용자 클릭 시에만 연결된다.
- [ ] 점수·순위·라이선스 메모가 변경되지 않았다.
- [ ] 확인되지 않은 API 동작을 주장하지 않았다.

## 7. 거부 패턴 기록법

새 결정은 의사결정 기록부에 항목을 추가하고, 대체된 이전 결정에는 대체됨을 표시한다. 아래 항목을 빠짐없이 적는다.

| 항목 | 기록 내용 |
|---|---|
| 결정 | 채택한 규칙 또는 변경 내용을 한 문장으로 |
| 근거 | 우선순위 단계와 관찰 요지를 일반 서술로 |
| 대안 | 검토했지만 채택하지 않은 선택 |
| 거부 사유 | 오염, 근거 부족, 토큰 불일치 등 구체 사유 |
| 영향 | 매핑 토큰, 화면, 컴포넌트 중 변경되는 대상 |
| 후속 | 확인 필요 해소 조건 또는 재심의 게이트 |

거부 패턴은 아래처럼 적는다.

> 결정: 관찰된 서비스의 최대폭 수치는 토큰으로 환산해서만 사용한다.  
> 근거: 캡처 분석 결과(로컬 전용, 저장소 미포함) — 서비스별 최대폭 편차 관찰.  
> 대안: 관찰 수치를 그대로 상수로 채택.  
> 거부 사유: 자체 토큰 체계와 충돌하고 화면별 폭 정책을 훼손한다.  
> 영향: 콘텐츠 최대폭, 거터 토큰.  
> 후속: G1 재심의 없이 적용 가능.

오염·오귀속·이미지 의존 근거는 거부 사유에 반드시 명시하고, 해당 관찰은 규칙 근거에서 제거한다.

## 8. 모듈 독립성과 명시적 링크

| 원칙 | 내용 |
|---|---|
| 기본 상태 | 각 모듈은 독립 라우트로 유지하고 자동 이동·암묵 연결을 하지 않는다 |
| 연결 생성 | 명시적 사용자 클릭이 발생한 경우에만 `ModuleLink`를 생성한다 |
| 연결 표시 | 연결 가능 지점은 `ModuleLinkChip`으로 의사를 표시한다 |
| 상태 유지 | 연결 후에도 원 모듈의 상태와 맥락을 유지한다 |
| 게이트 | 양산 모드 명세에서 연결 조건을 먼저 확인한다 |

자동 완성, 자동 추천 이동, 배경 실행 결과에 따른 임의 연결은 거부 패턴으로 기록한다.

## 9. 근거 서술과 경로 의존 금지

| 항목 | 규칙 |
|---|---|
| 고지 문구 | 규칙 문서와 본 문서 서두에 로컬 전용 자료 사용과 경로 비의존을 명시한다 |
| 근거 형식 | `캡처 분석 결과(로컬 전용, 저장소 미포함) — 관찰 요지` 형태의 일반 서술 |
| 금지 기재 | 캡처 자산의 구체 경로, 파일명, 스크린샷 이름, 링크, 주소 |
| 시각 표현 | 이미지 열람을 암시하는 서술과 시각적 스타일 단정 금지 |
| 보류 표기 | 부분 관찰·오염 의심·데이터 미확보는 `확인 필요` |
| 근거 출처 우선 | 공식 가이드가 있으면 관찰보다 우선 |

경로가 없어도 규칙 ID와 서비스명만으로 규칙을 식별할 수 있어야 한다.

## 10. 보호 대상과 금지 사항

| 항목 | 상태 |
|---|---|
| 점수·순위·라이선스 메모 | 변경 금지 |
| 지원하지 않는 API 동작 | 주장 금지, 관련 명세는 확인 필요로 유지 |
| 직접 코드·마크업·스크린샷 재사용 | 0건 유지 |
| 서비스 전용 글꼴·색상·상수 | 자체 토큰으로 환산 후에만 사용 |
| 확인 필요 규칙 | 근거 보강 전 구현 승인 금지 |
| 캡처 자산의 경로·파일명·링크·주소 | 문서 기재 금지(자체 KB-ID·문서 역할명은 허용) |

보호 대상이 변경된 것이 확인되면 G5에서 변경을 되돌리고 새 결정을 다시 기록한다.

## 11. 적용 예

| 단계 | 적용 내용 |
|---|---|
| 관찰 | 이름 없는 컨트롤이 서비스별로 편차가 있음을 확인 |
| 게이트 | G0에서 시각 관찰 표현 제거, 일반 서술로 교체 |
| 설계 | `UXR-CAN-005`를 공통 규칙으로 승격 |
| 매핑 | 전 컨트롤에 접근 가능한 이름 부여로 연결 |
| 점검 | G3에서 이름 없는 컨트롤 0개 확인 |
| 기록 | 거부 패턴과 대체 근거를 의사결정 기록부에 추가 |
