## 1. 디자인 콘셉트: Creative Operations Studio

크리에이티브 제작 도구의 "결과물 중심 작업 공간"과 SaaS 운영 대시보드의 "상태·데이터 밀도"를 하나로 결합한다.

레퍼런스 7개에서 가져오는 것은 **화면 전체가 아니라 인터랙션 단위의 패턴**이다.

| 레퍼런스 | 가져오는 인터랙션 단위 | 가져오지 않는 것 |
|---|---|---|
| Snipit | 레퍼런스 검색/필터, 보드, 브랜드 아카이브 | 마케팅 랜딩 페이지 전체 |
| Foreplay | 스와이프 파일 카드, 위닝 패턴 표시, 성과/크리에이티브 병렬 보기 | 다크 랜딩 히어로 전면 복제 |
| MONOV | 입력 → 4장 결과 그리드 → 편집/히스토리 흐름, 내 스타일 | 생성 재구성 코드 그대로 사용 |
| Creatify | 포맷 카탈로그, 소스 연결 → 생성 → 배포 흐름 | 대형 히어로 카피/가격 섹션 |
| Postiz | AI 에이전트 연결 카드, 채널 연결 상태, 캘린더/자동화 개념 | 보라 다크 테마 그대로 |
| Buffer | 채널 타일, PUBLISH/CREATE/COMMUNITY/INSIGHTS 4축 구조, AI assistant | 크림색 랜딩 톤 그대로 |
| Motion | 진본 출처 확인(로컬 캡처 분석 결과(저장소 미포함)) → Visual-first 리포트/그룹화/AI 태깅 패턴 참고 | 출처 불일치 자료(Creatify)를 Motion 근거로 단정 |

## 2. 디자인 원칙

1. **결과물이 화면의 중심이다.** 생성 이미지/영상/카피 카드가 가장 큰 시각 비중을 갖는다.
2. **AI는 상태가 보이는 비동기 작업이다.** `queued → running → streaming → reviewing → approved → published`를 숨기지 않는다.
3. **사람이 승인한다.** 모든 생성 결과는 기본적으로 `초안`이며, 승인 전 발행 버튼은 비활성 또는 확인 모달을 거친다.
4. **한 화면에 주 액션은 하나다.** 보조 액션은 드로어/메뉴/오버플로에 둔다.
5. **비용과 출처를 표시한다.** 모델 Provider, 토큰/이미지 장수, 예상 비용, 프롬프트 버전을 결과물에 메타로 붙인다.
6. **빈 화면을 설계한다.** "데이터 없음"이 아니라 "첫 레퍼런스를 저장하세요" 같은 다음 행동을 제시한다.
7. **토큰과 재사용 컴포넌트만 쓴다.** 임의 색상·간격·radius를 화면에 직접 박지 않는다.
8. **이모지 아이콘 금지.** Lucide 계열의 선형 아이콘과 텍스트 라벨을 사용한다.
9. **한국어 UI 카피.** 영문 원어를 그대로 섞지 않고, 필요할 때만 괄호로 병기한다.
10. **과도한 카드 중첩 금지.** 카드 안 카드 대신 구분선·섹션 헤더·탭을 사용한다.

### 3-4. 아이콘·모션

- 아이콘: Lucide, 16/20px, `stroke-width: 1.75`, 라벨과 함께 사용.
- 모션: hover 120ms, drawer 180ms ease-out, skeleton pulse 1.4s. `prefers-reduced-motion`에서는 pulse/transition 비활성.
- 그라데이션·네온·글래스모피즘·이모지 아이콘 사용 금지.

│   │   ├── 이미지 작업: 리사이즈/크롭, 색보정·그레이딩, 배경 제거·교체, 객체 편집(inpaint/outpaint), 업스케일, 스타일 변환

전역 객체: `Campaign`, `BrandKit`, `CollectSource`, `CollectedItem`, `Asset`, `Job`, `ProviderConnection`, `CostRecord` — 화면 어디서든 우측 패널로 연결된다.
모듈 전용 객체: `OwnContent`, `ContentSeries`, `IdeaBacklog`, `OverlapFlag` (S5) / `MetricSeries`, `Forecast` (S6) / `AudienceDataset`, `Segment`, `SegmentMember` (S7) / `ProductionMode`, `ReferenceHit`, `ManualReference`, `VideoAnalysis`, `VideoIntent`, `Shot`, `RenderGate`, `RevisionRequest` (S8). 여기에 S8 소스·변환 워크스페이스 객체 `InputMode`, `MediaSource`, `TransformOperation`, `CompositeLayer`, `RightsConfirmation`, `TransformPreview`가 추가된다. 이들은 서로 FK를 갖지 않고 `ModuleLink`로만 참조된다. S8 내부 3탭의 객체도 탭별로 분리되며, 수정 탭에는 사용자가 명시적으로 지정한 `shot_id`/timecode만 전달되고 소스·변환 객체도 자동 주입되지 않는다.

> **설계 원칙 재확인**: 캡처한 7개 서비스는 인터랙션·토큰 참고용일 뿐이다. 실제 수집/검색/분석 파이프라인은 이 프로젝트에 맞춰 **직설계·직구현**하며, 오픈소스 수집 툴은 라이선스를 확인한 뒤 라이브러리/서비스 형태로만 사용한다. S0의 소스별 탐색은 "수집기"를 사용자에게 노출하는 네비게이션이며, 크롤링 대상·범위·주기는 설정에서 통제한다.

> **모듈 분리 원칙 (최우선)**: S0(남의 콘텐츠 수집) / S5(우리 콘텐츠) / S6(성과·예측) / S7(오디언스) / S8(영상 분석·제작·수정)는 **서로 다른 질문에 답하는 별도 화면**이다.
> 1. 각 모듈은 독립 라우트·독립 상태·독립 빈 화면을 가진다. 진입은 사이드바에서 직접 한다.
> 2. **연결은 기본 off.** 사용자가 "가져오기 / 연결 / 적용" 버튼을 눌러야만 `ModuleLink`가 생긴다.
> 3. 연결은 **식별자 참조만**(`content_id`, `segment_id`). 데이터를 복사하거나 자동 동기화하지 않는다.
> 4. 한 모듈에 데이터가 없어도 나머지는 샘플 데이터로 정상 작동한다(차단 전파 금지).
> 5. 공유 대상은 디자인 토큰·App Shell·JobDrawer·ProviderConnection 뿐이다. 모듈 내부 컴포넌트는 재사용하지 않는다.
> 6. 설정의 "모듈 연결"에서 생성된 링크를 한눈에 확인/해제할 수 있다.
> 7. S8은 S2의 서브탭이 아니라 독립 라우트이며, 내부 3탭(분석/제작/수정)도 상태를 섞지 않는다. S2로 결과를 넘길 때도 사용자가 명시적으로 클릭해야 한다.
> 8. S8 제작 유형은 **프로젝트 단위 명시적 선택(기본값 미선택)**이다. 자동 감지·자동 변경 금지, 변경 시 확인 다이얼로그로 안내하고 기존 결과를 자동 덮어쓰지 않는다. 3탭 상태 분리는 유형이 바뀌어도 유지된다.
> 9. S8 레퍼런스 서치는 **사용자가 검색 버튼을 누르거나 수동 입력하거나 S0 결과를 클릭할 때만** 동작한다. `ModuleLink(s0→s8)`는 클릭으로만 생성되고 자동 로드·복제·미디어 바이트 저장을 하지 않는다(원문 URL·썸네일 URL·타임코드만).
> 10. S8 소스 모드는 기본 `generate_new`다. `transform_source` / `composite` 전환, S5 자산 연결은 사용자 명시 클릭과 권리 확인(`rights_flag`, `rights_confirmed_by`) 후에만 진행하고, 이전 버전은 보존한다. 서드파티 레퍼런스는 메타데이터 전용이며 프레임을 내려받거나 분석하지 않는다.
> 11. S8 변환·합성 결과는 신규 생성과 동일하게 4게이트를 통과한다. 전체 영상 자동 재렌더·모듈 자동 동기화·ComfyUI/Blender 웹 서비스(무단 코드 실행 및 라이선스 리스크)는 제외하며, 실제 어댑터는 공식·라이선스 확인된 공급자 또는 검증된 로컬 도구만 Phase B/C에서 예산·라이선스 승인 후 사용한다.

   ↓
S4 CSV 성과 업로드 → 지표 비교 → AI 개선안 → 새 브리프로 순환

**독립 진입 시나리오 (자동 연결 없음)**

```text
[우리 콘텐츠 관리] S5 진입 → 보관함(수동/CSV) → 겹침 배지 확인 → 시리즈 지정

      → (선택) S0 결과 "S8 참고로 가져오기" 클릭 시에만 ModuleLink(s0→s8). 미디어 바이트 미저장
   → 소스 모드 선택(분석 전): generate_new(기본 표시) / transform_source / composite. 기존 아티팩트 있으면 확인 다이얼로그 → 이전 버전 보존
       → 미디어 소스: 사용자 업로드 / 사용자 제공 URL / (선택) S5 자산 "S8에서 소스로 사용" 클릭 시 ModuleLink(s5→s8)
       → 서드파티 레퍼런스는 메타데이터만(프레임 다운로드·분석 없음), 변환·합성은 rights_flag·rights_confirmed_by 확인 후 진행
       → 변환·합성 워크스페이스: 작업 칩 선택 → 레이어·마스크(스텁) → 전·후 비교 → 작업별 예상 비용·시간 확인
       → 변환 샷은 Shot으로, 합성 레이어는 Composition3D 스키마로 동일 4게이트에 투입(우회 없음)
    → 분석 탭: 내용(훅/구조/메시지/CTA/타깃/감정곡선 + timecode) + 기술(앵글/기법/전환/조명/구도/편집 + confidence)
   → 제작 탭: 자연어 입력 → 용어 매핑 미리보기(원문/표준용어/근거/신뢰도) → 사용자 확인 → VideoIntent
   → 게이트 1 콘티 → 게이트 2 3D 구도 스키마(시뮬레이션) → 게이트 3 애니매틱(저해상도 스텁) → 게이트 4 샷별 렌더(DryRender)
   → 수정 탭: shot_id/timecode 지정 → 영향 범위·예상비용 미리보기 → "이 샷만 수정"
   → (선택) 결과 참조만 S2에 전달(사용자 클릭). 전체 영상 즉시 생성/전체 재생성 없음
```

> 위 네 흐름은 **S0~S8 파이프라인과 자동으로 이어지지 않는다.** 사용자가 각 진입점에서 시작하고, 연결 버튼을 눌렀을 때만 `ModuleLink`가 기록된다. S8의 3개 탭도 서로 자동으로 데이터를 읽지 않는다.

## 7. 접근성·반응형

- 대비: 본문 4.5:1, 큰 텍스트/UI 경계 3:1 이상.
- 모든 인터랙션은 키보드로 도달 가능, 포커스 링은 `border.strong` 2px.
- 표는 `<table>` 의미 구조 유지, 숫자는 `font.mono` + 우측 정렬.
- 이미지/카드에는 대체 텍스트 또는 `aria-label` 제공.
- 1440×900 기준. 1280 이하에서 우측 패널은 오버레이로 전환, 1024 이하에서 사이드바는 접힘, 768 이하에서는 10개 화면(Collector·Own Content·References·Studio·Publishing·Insights·Performance·Segments·Video Workbench·SEO & Search Growth)을 세로 스택으로 재배치(단, MVP는 데스크톱 우선). S9 SEO & Search Growth의 상세 명세는 `SEO-GROWTH-SPECS.md`에 있고 이 문서에서는 화면 수에만 포함한다.

## 8. 디자인 스킬·검수 도구 가용성

구현 환경에서 사용 가능한 도구와 스킬을 확인해 적용한다. 요청된 디자인 스킬은 기본 저장소에 포함되지 않으므로 설치 여부는 구현 단계에서 확인한다.

| 스킬/리소스 | 환경 내 상태 | 계획 단계 배치 |
|---|---|---|
| UI UX Pro Max | 미설치 (외부 저장소만 존재) | 설치 시 0~1단계 스타일/UX 가이드 수립. 현재는 수동 체크리스트 대체 |
| Anthropic Frontend Design | 미설치 | 1단계 비주얼 방향, "AI 기본 디자인 회피" 원칙 수립 시 참조 |
| Impeccable | 미설치 | 2~3단계 `/polish`, `/audit` 성격의 마감 검수 시 참조 |
| Vercel Web Design Guidelines | 미설치 | 3단계 접근성/성능/UX 가이드라인 체크리스트로 참조 |
| shadcn/ui + Blocks | 스킬 아님, 미설치. npm/bun도 미설치 | 2단계 React/Tailwind 조립 레퍼런스 (MIT, 고지 유지) |
| 21st.dev | 스킬 아님, 미설치 | 2단계 영감/블록 참조. 무료 일 2회 복사 제한, 유료 플랜 확인 필요 |
| browser 스킬 | 환경에 따라 사용 가능(설치 여부 확인) | 3단계 실제 렌더링, 스크린샷, Lighthouse, 콘솔/네트워크 검수 |

Figma는 필수가 아니다. 대신 `browser.screenshot` + `browser.preview`, `browser.lighthouse`, `browser.evaluate`(대비비·오버플로·aria 검사), `browser.console/network`를 검수 도구로 사용한다.

## 10. 이 문서의 수용 기준

- [ ] 모든 화면이 위 토큰만 사용한다.
- [ ] 화면마다 빈/로딩/성공/실패/승인 상태가 정의되어 있다.
- [ ] AI 생성 작업은 항상 Provider·모델·비용·상태를 노출한다.
- [ ] 이모지 아이콘, 그라데이션, 글래스모피즘이 없다.
- [ ] React/Tailwind/shadcn/ui 구조로 그대로 매핑 가능한 컴포넌트 이름이 `COMPONENT-SPECS.md`에 정의되어 있다.
- [ ] S8이 10개 화면의 독립 라우트로 진입하고, S2 서브탭이 아니다. S9 SEO & Search Growth의 상세 명세는 `SEO-GROWTH-SPECS.md`에 있고 여기서는 라우트 수에만 포함한다.
- [ ] S8 제작 유형(실사/숏폼/영화/영상/애니메이션/모션그래픽)이 프로젝트 단위 명시 선택(기본 미선택)이고 자동 감지·자동 변경이 없다.
- [ ] S8 유형 변경 시 확인 다이얼로그가 기존 결과를 자동 덮어쓰지 않는다.
