# IMPLEMENTATION-PLAN — 1~2일 MVP 실행 계획 (수집기 + 독립 모듈 개정)

작성일: 2026-11-22  
전제: **문서 작성만 수행, 실제 웹앱 코딩은 하지 않음.** 이 문서는 "착수 시 무엇을 어떤 순서로 만들지"에 대한 실행 지침이다.  
관련 문서: 제품 요구사항, 아키텍처, 디자인, 컴포넌트, 화면 설계 문서(각 문서는 별도로 관리).

> **2026-11-22 개정**: 기존에는 수집을 후속으로 뒀으나, 사용자 결정으로 **MVP에 Collector(S0)를 포함**한다. 캡처는 참고용이고 수집·정규화·분석 파이프라인은 이 프로젝트용으로 직접 설계·구현한다. 추가로 **S5 우리 콘텐츠 허브(최소), S6 성과·예측(샘플 뷰), S7 오디언스 세그먼트(샘플 뷰), S8 비디오 워크벤치(Phase A-lite + 미디어 변환·합성 확장), S9 SEO & Search Growth(Phase A 별도 트랙)**를 독립 모듈로 편성한다. Motion은 로컬 캡처 분석 결과(저장소 미포함)에서 진본이 확인되어 그룹화/태깅/모멘텀 패턴만 참고한다. **전체 라우트는 10개**이며, 모든 모듈은 기본 "연결 안 함"이고 사용자 클릭으로만 `ModuleLink`가 생성된다. 확정 정책 29건은 `DECISION-LOG.md` J장을 따른다.

> **문서 작성 규칙**: 이 문서와 관련 기획 문서에는 저장소에 포함되지 않는 캡처 자료의 경로·파일명·링크·스크린샷 위치를 기재하지 않는다. 근거가 필요하면 **로컬 캡처 분석 결과(저장소 미포함)를 일반 원칙으로 정리**해 서술한다. 서비스명·점수·순위는 기존 감사 맥락을 유지하되, 특정 앱의 기능을 그대로 구현한다는 표현은 쓰지 않는다.

## 0. 현실성 판정 (먼저 읽을 것)

1~2일 MVP의 목표는 **"경쟁사 콘텐츠 수집(S0) → 우리 콘텐츠 관리(S5) → F1~F7 작업 흐름 → 성과·예측(S6)·오디언스(S7)·비디오 워크벤치(S8, Phase A-lite + 미디어 확장)까지 모듈별로 독립된 화면을 직접 눌러 확인하고, S9 SEO & Search Growth는 별도 트랙에서 기본 '연결 안 함' 상태로 확인하는 동작 프로토타입"**이다.

- **포함**: S0 Collector(4 파트 탐색, 수동+RSS+공개 API), S5 Own Content(보관함·겹침·시리즈·백로그, 최소), S1 References, S2 Studio, S3 Publishing(Dry-run), S4 Insights, S6 Forecast(샘플 + 이동평균), S7 Segments(샘플 UI), **S8 Video Workbench(Phase A-lite: 제작 유형 선택·레퍼런스 서치·분석 스키마·용어 확인·4단계 샘플 게이트·샷 단위 수정 프리뷰 + 입력 소스 모드·미디어 변환/합성 스키마·권한 게이트·before/after·비용 미리보기)**, **S9 SEO & Search Growth(Phase A 별도 트랙: 진단 룰 엔진·키워드/콘텐츠 개선안·예산 추천 시뮬레이션·샘플 취합 대시보드)**, 개선 순환, ModuleLink(수동 연결만).
- **의도적 제외**: 실제 소셜 발행/결제, 30+ 채널 OAuth, 실제 영상 생성·렌더(**진짜 렌더 어댑터·실제 3D 프리뷰·diff 재렌더·유형별 모션 내보내기·실제 이미지/영상 변환·합성 어댑터는 Phase B/C 또는 제외**), 심사·토큰 필요한 Ad Library 연동, 플랫폼 ToS 금지 스크래핑, 미디어 재호스팅, 다중 사용자/권한, Postiz 포크, n8n 사용자용 빌더. **S9는 실제 SEO API 호출·쿼터 운영·포털 확장·스크래핑/로그인 우회/유료벽 우회를 제외**(Phase A는 수동 입력·샘플·룰 기반 드라이런만).
- **모듈 MVP의 현실적 한계**: S5는 수동/CSV만, S6은 샘플 데이터 + 이동평균 baseline만, S7은 샘플 좌표 + k 선택 UI만. **S8은 제작 유형 6종 중 사용자 명시 선택(기본 미선택, 자동 감지·자동 변경 금지) + 레퍼런스 서치(사용자 트리거 공개 소스 스텁/샘플 + 수동 URL·메모·타임코드, S0는 클릭 시 `ModuleLink`) + 2계층 분석 스키마 + `TermMapping` 사용자 확인 게이트 + 콘티/3D 구도 스키마/애니매틱/단계별 렌더 샘플 게이트 + 샷·타임코드 단위 수정 프리뷰 + 용어 사전 설정까지.** 여기에 **입력 소스 모드 3종(`generate_new`/`transform_source`/`composite`)과 실제 사진·이미지·영상 업로드 기반 변환·합성 UI 스키마, `rights_flag`/`rights_confirmed_by` 권한 게이트, before/after 프리뷰, 샘플 단가 기반 비용 미리보기**를 추가한다. 결과는 기존 4게이트를 그대로 통과하며 게이트를 추가·변경하지 않는다. **S9은 수동 입력·샘플 + 룰 기반 진단/예측 + Dry-run만** 하고 공식 API 호출은 하지 않는다. **KMeans 실제 실행, ML/DL 학습, CRM 연동, S8의 실제 렌더·변환·합성 어댑터(웹서비스형 이미지/영상 처리 포함)·실제 3D·diff 재렌더·유형별 실제 렌더/모션 내보내기·레퍼런스 서치 실제 API 호출/쿼터 운영, S9의 실제 SEO API 호출·쿼터·포털 확장은 Phase B/C 또는 제외.** 모듈 간 자동 연결·자동 동기화는 만들지 않는다(사용자 클릭으로만 `ModuleLink` 생성).
- **수집 MVP의 현실적 한계**: 4개 파트 **UI/탐색은 전부** 만들고, 어댑터는 **수동 입력 + RSS(항상) + 공식 API 1~2개(키 발급 시)** 로 제한한다. 키가 없는 소스는 "연동 대기" 배지로 표시하고 실제 호출하지 않는다.

> 로컬 Qwen 27B는 VRAM 7.6/8GB를 점유하므로 **동시 추론 1개**, `num_ctx 4096` 유지. 생성은 비동기 Job으로 처리한다(수집 Job도 동일 프레임워크 재사용).

## 2. Day 1 — 골격 + 수집기 + 레퍼런스 (S0 → F1)

### 오전: 프로젝트 골격 + Collector

1. Vite + React + TS + Tailwind v4 초기화, shadcn 초기화, 토큰은 디자인 설계 값으로 주입(`--primary` 등).
2. FastAPI 스켈레톤 + SQLite `create_all` + CORS(로컬 only). `CollectSource/CollectJob/CollectedItem` 스키마 포함.
3. App Shell 구현: 240px Sidebar(그룹 라벨 `[수집·자산]/[작업]/[분석]`, 10개 메뉴 — S8 Video Workbench, S9 SEO & Search Growth 포함), Topbar(프로젝트/Provider/검색/사용량), 라우팅 10개 슬롯.
4. S0 Collector UI: `CollectTargetForm` + **VerticalTabs(전체/영상/이미지/블로그/뉴스, 독립 URL)** + `SourceList` + 결과 그리드 + `ComplianceBadge`.
5. `CollectAdapter` 인터페이스 + `ManualAdapter`(URL/메모 직접 입력), `RssAdapter`, `AdLibraryMetaAdapter` 스텁("연동 대기").
6. 키가 있으면 `YouTubeAdapter`(영상+썸네일) 또는 `NaverSearchAdapter`(뉴스+블로그) 중 **1개 우선 연결**. GDELT는 영문 뉴스 백업으로 선택.
7. 정규화·중복제거(URL + external_id + content_hash) + `CollectedItem` 저장. 미디어는 재호스팅하지 않고 원문/썸네일 URL만 보관.
8. `CollectJob` 상태(진행/중복 skip/대기/실패 재시도)를 JobDrawer에 표시.

### 오후: References + S5 Own Content Hub (최소)

9. S1: S0에서 "분석" 버튼으로 이관된 항목 + 직접 저장한 레퍼런스 목록, 보드 필터, TanStack Table, 빈/로딩 상태. 이관 시 `source/source_mode/fetched_at/terms_snapshot` 보존.
10. S1 → "AI 분석": 로컬 추론에 후킹/메시지/CTA 추출 프롬프트 → `Analysis` 저장 → 우측 패널 표시.
11. S5 골격: `OwnContent` 테이블 + 수동/CSV import(샘플 템플릿) + 서브탭(보관함/겹침·시리즈/아이디어 백로그). **S0 데이터는 자동 로드하지 않는다.**
12. S5 겹침: 제목/카피 토큰 Jaccard로 `신규/유사/확장` 배지 + 기존 콘텐츠 링크. 시리즈 태그와 아이디어 카드 작성까지.
13. ModuleLinkService: `link(source, source_id, target, target_id, created_by)` / `unlink()` + 설정의 연결 목록 UI. S0 "참고로 가져오기"와 S5 "이 아이디어로 기획" 버튼에만 연결(자동 링크 없음).

**Day 1 완료 기준**: 분야/경쟁사를 등록해 4개 파트 탭에서 결과(또는 연동 대기/Empty)를 보고, 선택 항목이 S1로 이관되어 AI 분석 결과가 보이며, S5에서 우리 콘텐츠를 등록해 겹침 배지와 아이디어 카드를 확인할 수 있다. S0↔S5 연결은 버튼을 누를 때만 생긴다.

## 3. Day 2 — 기획·제작·검수·발행·분석·예측·세그먼트·비디오 (F2~F7 + S6/S7/S8/S9)

### 오전: S2 Studio + S3 Publishing

14. S2: 브리프 생성 폼(상품/타깃/브랜드 톤, 참고 레퍼런스 + S5 아이디어 선택) → `Job` 생성 → 로컬 추론 스트리밍 → `Brief` 저장.
15. 콘셉트 3안 생성 → 1안 선택 → 카피 + 이미지 프롬프트 생성.
16. 4장 결과 그리드(카드 + 재생성/수정 버튼) 구현. 실제 이미지는 후속이므로 MVP에서는 플레이스홀더 + 프롬프트 텍스트 표시.
17. 검수 탭: 체크리스트(상품명/가격/금지어/브랜드 톤) + 승인 버튼 → `Review.approved`, 상태 배지.
18. S3: 채널 타일(연결 필요 배지), 게시물 큐 + 주간 그리드, 채널별 텍스트 변환 미리보기.
19. "예약" 클릭 → `PublishJob.scheduled` + **Dry-run 배지**. 실제 외부 전송 코드 없음.

### 오후: S4 Insights + S6 Forecast + S7 Segments + 순환 + 마감

20. S4: CSV 업로드 → 지표 매핑(노출/클릭/광고비/상담/계약) → Recharts 카드/막대 + Top 콘텐츠 테이블.
21. "개선안 만들기" → 로컬 추론이 지표 기반 제안 생성 → "이 개선안으로 새 브리프" 버튼이 S2 브리프 폼에 값 채워 이동(**F7→F2 순환**).
22. S6: 별도 라우트. `MetricSeries`(샘플/CSV) → 이동평균 baseline 예측 → 실선/점선 차트 + **예측·신뢰도·모델 배지**. "S5 콘텐츠와 연결"은 클릭 시 `ModuleLink(s6→s5)`만 생성.
23. S7: 별도 라우트. `AudienceDataset`(샘플, 식별자 제외 기본) → 변수 체크 → k=3~6 선택 → 군집 카드/산점도 + 프로필(사람 편집). 실제 KMeans는 Phase B이므로 `샘플` 배지 필수.
24. 브라우저 스킬로 1440 스크린샷 + 콘솔/네트워크 오류 확인, Lighthouse 접근성, 대비비·가로 오버플로 점검.
25. 디자인 수용 기준 체크, Dry-run/샘플/예측/개인정보 배지 확인, 모듈 간 자동 연결이 0건인지 확인, 문서-화면 라벨 일치 확인.

**Day 2 완료 기준**: 승인→예약(Dry-run)→성과 업로드→개선안→새 브리프까지 클릭 흐름이 끊기지 않고, S6/S7이 독립 진입되어 샘플 상태를 표시하며, 모듈 간 연결은 사용자 클릭으로만 기록된다. 모든 화면에 빈/로딩/성공/실패 상태가 존재한다.

### 추가 트랙: S8 Video Workbench (Phase A-lite, S2와 독립)

26. S8 별도 라우트 + 3탭(분석/제작/수정) **독립 상태**. S2의 브리프·Job·승인 상태를 재사용하지 않고, 연결은 사용자가 "참고로 가져오기"를 누를 때만 `ModuleLink(s8→s2)` 생성.
27. **제작 유형 선택(프로젝트 단위)**: `실사 / 숏폼 / 영화 / 영상 / 애니메이션 / 모션그래픽` 6종 중 **사용자가 명시적으로 1개 선택**(기본 미선택). 자동 감지·자동 변경 금지, 변경 시 재확인. 선택 값이 분석 차원·구도 스키마·게이트 산출물·템플릿 필터·비용 프로파일을 결정한다(제작 유형별 명세는 `design/PRODUCTION-MODE-SPECS.md` 참조). 미선택 시 분석·제작 게이트 잠금.
28. **레퍼런스 서치**: 자동(사용자가 누를 때만 실행하는 공개 소스 검색 — 어댑터 스텁/샘플 결과) + 수동(URL·메모·타임코드 입력) 이원 UI. 공식 API·공개 피드·공개 메타만 대상으로 하고 로그인/유료벽/스크래핑 우회는 제외. 미디어 바이트 미저장, provenance(출처·방식·수집 시각·약관 스냅샷) 보존. **제작 유형별 검색 축**은 자체 레퍼런스 검색 플레이북(별도 관리)의 일반 원칙을 따른다. S0 결과는 "S8로 가져오기" 클릭 시에만 `ModuleLink(s0→s8)` 생성(자동 동기화·복제 금지). **실제 API 호출·쿼터 운영은 Phase B.**
29. 분석 탭: 콘텐츠 분석(훅·메시지·CTA·톤) + 기술 분석(카메라앵글·기법·전환·조명·구도·편집) 2계층 스키마 UI. 레퍼런스 서치 결과를 입력으로 받고 **제작 유형별 분석 차원 필터**를 적용한다. 비전문가 자연어 문장을 `TermMapping`(표준 용어 + 원문 근거)으로 매핑해 **사용자 확인 게이트**에서 수정·확정. 미확정이면 콘티 게이트 잠금. 숏폼/모션그래픽 용어는 자체 숏폼 구성·모션그래픽 지식(별도 관리)의 안정 ID를 참조한다.
30. 제작 탭: 4단계 게이트 ①콘티 → ②3D 구도 스키마 → ③애니매틱 → ④단계별 렌더. **유형별 구도/산출물/템플릿 필터**를 각 게이트에 적용하고, 드라이런 어댑터의 샘플 프리뷰/스켈레톤만 표시. 명시적 승인 후에만 다음 단계로 진행. **전체 자동 렌더·모션 내보내기는 실행하지 않는다**(Phase B/C).
31. 수정 탭: 샷 ID/타임코드 선택 → 해당 구간만 개정 요청 → 영향 구간 프리뷰 + 샷 단위 개정 메모 저장. 전체 재렌더를 트리거하지 않는다(diff 재렌더·유형별 모션 재내보내기는 Phase B/C).
32. 설정: 용어 사전(비전문가 표현 ↔ 표준 촬영·편집 용어) 목록/추가/수정 UI + `TermMapping` 이력. 자체 전문 지식베이스(별도 관리)의 안정 ID를 참조한다.

**S8 기본 완료 기준**: 제작 유형이 기본 미선택이고 사용자 클릭으로만 선택·변경되며, 3탭 상태가 서로 섞이지 않는다. 레퍼런스 서치는 사용자 트리거/공개 범위/수동 입력만 제공되고 S0 링크는 클릭 시에만 생성된다. 자연어→용어 확인 전에는 콘티가 잠기고, 콘티→3D 스키마→애니매틱→렌더 샘플까지 단계별 승인으로만 진행되며, 샷/타임코드 수정이 전체 렌더를 트리거하지 않는다. 렌더/3D/재렌더/모션 내보내기/실제 검색 API 화면에는 `Phase B/C` 배지가 붙는다.

#### S8 확장 태스크 — 미디어 소스·변환·합성 (Phase A: 스키마·샘플·드라이런만)

33. **입력 소스 모드 3종**: `generate_new` / `transform_source` / `composite`를 제작 탭에 명시 선택 UI로 둔다(기본 `generate_new`, 자동 전환 금지). `transform_source`·`composite`는 사용자가 직접 사진·이미지·영상을 업로드한 뒤에만 활성화한다.
34. **변환·합성 스키마 UI**: 이미지는 크롭/색보정/배경 제거·교체/객체 편집/업스케일/스타일 변환, 영상은 트리밍/리타이밍/그레이딩/배경 교체/객체 제거/스타일 변환/프레임 보간, 합성은 레이어(배경·인물·제품·텍스트·로고·이펙트) + 마스킹 + 블렌딩 + 레이어 타이밍을 **조작 스키마와 샘플 프리뷰로만** 노출한다. 실제 처리·렌더는 실행하지 않는다(`Phase B/C` 배지, 실제 어댑터·웹서비스형 이미지/영상 처리는 Phase B/C 또는 제외 유지).
35. **권한 게이트**: 업로드·변환·합성 전에 `rights_flag`와 `rights_confirmed_by`를 필수 확인한다. 미확인이면 변환·합성 미리보기 잠금. 타사 레퍼런스 미디어는 **메타데이터 전용**(출처·식별자·약관 스냅샷)으로 두고 **프레임 다운로드·프레임 분석을 금지**한다.
36. **before/after + 기존 4게이트**: 원본/결과 나란히 비교 프리뷰와 변경 메모를 제공하고, 결과물은 **기존 4게이트(콘티→3D 구도 스키마→애니매틱→단계별 렌더)를 그대로 통과**한다. 게이트 추가·우회·자동 통과는 없다.
37. **비용 미리보기**: 샘플 단가·예상 소요량 기반의 추정 비용 카드와 `추정/드라이런` 배지를 표시한다. 실제 결제·청구·공급자 호출은 없으며 실제 단가 확정은 Phase B/C다.

**S8 확장 완료 기준**: 소스 모드가 명시 선택(기본 `generate_new`)이고, 변환/합성은 스키마·샘플·드라이런에 머무르며, `rights_flag`/`rights_confirmed_by` 미확인 시 잠기고, 타사 레퍼런스 미디어의 프레임을 내려받거나 분석하지 않는다. before/after와 비용 미리보기가 표시되되 결과는 기존 4게이트를 그대로 통과한다.

### 추가 트랙: S9 SEO & Search Growth (Phase A, S6과 독립)

38. S9 **별도 라우트** + 4서브탭(진단 / 키워드·콘텐츠 / 예산·예측 / 취합·개선). 기본값은 **"연결 안 함"**이며 S2·S5·S6 상태를 재사용하지 않는다. 연결은 클릭 시에만 `ModuleLink(s9→s2)` / `ModuleLink(s9→s5)`를 생성한다.
39. 진단 탭: 수동 입력·샘플 사이트 데이터로 **기술/온페이지/콘텐츠 진단 룰 엔진**(룰 ID·심각도·근거·권장안)과 상태 배지를 표시한다. 실제 크롤링·SERP 수집은 하지 않는다.
40. 키워드·콘텐츠 탭: 키워드 갭·검색 의도 매핑과 제목/메타/구조 개선안을 **룰 기반 샘플**로 생성하고, 적용 버튼은 클릭 시에만 S2 브리프/S5 콘텐츠로 `ModuleLink`를 만든다.
41. 예산·예측 탭: SERP 추적은 **공식 데이터 한정 스텁/샘플**(Phase A), SEO 투자비용↔성과 예측(CPC/CAC/ROAS/유입)과 예산 배분 추천은 룰 기반 시뮬레이션으로 표시하고 `예측/신뢰도/모델/샘플` 배지를 붙인다.
42. 취합·개선 탭: 진단·키워드·예측·집행 결과를 **취합 대시보드**로 보여주고, 개선 루프는 사용자가 "브리프 만들기"/"콘텐츠 만들기"를 누를 때만 연결한다(자동 개선 실행 없음).
43. 공개·공식 범위 가드: **사용자가 직접 로그인/OAuth로 연동한** 소유 확인 검색 콘솔 계정, 광고 계정의 공식 키워드 도구, 공식 검색 API, 공개 피드/메타, 수동 입력만 **스텁/샘플 대상**으로 명시하고, 스크래핑·로그인 우회·유료벽 우회 금지 배지를 표시한다. 실제 호출·쿼터·인증은 Phase B, ML 최적화와 포털 확장은 Phase C다. 시스템 주도 로그인·토큰 대입력은 구현하지 않는다.
44. S9 문서 정합: S6과 지표를 복제하지 않고 참조만 하며, 라우팅/배지/빈·로딩·성공·실패 상태를 S8 트랙과 동일한 품질 기준으로 검수한다.
45. **비용 승인 게이트 명세(Phase A는 UI/상태만)**: 사용자가 직접 로그인/OAuth로 연동하는 `OAuthConnectButton`, 실행별 `ConsentCheckbox`, 임계값 초과 `CostApprovalDialog`, `SpendCapGauge`(기본 0원), `ApprovalHistoryTable`을 정의한다. Phase A에서는 실제 호출 없이 시뮬레이션 배지만 붙이고, Phase B/C에서 승인 토큰 없이 실행되면 거부되도록 `CostApprovalService`를 연결한다(J-27~29).

**S9 Phase A 완료 기준**: 별도 라우트에서 기본 "연결 안 함"으로 진입되고, 4서브탭이 샘플·수동·룰 기반으로 동작하며, 예측에는 배지가 붙고, 개선 루프는 클릭 기반 `ModuleLink`로만 생긴다. 계정 연동은 사용자 직접 OAuth 방식으로 명세되고, 비용 승인 게이트(동의·2차 팝업·상한·이력)의 UI/상태가 정의된다. 실제 SEO API 호출·쿼터·포털 확장·과금 화면에는 `Phase B/C` 배지가 붙는다.

## 6. 완료 후 다음 단계 (MVP 아님)

1. 광고 라이브러리 공식 연동: 심사·토큰 완료 후 메타데이터 한정 어댑터 활성화.
2. Provider 다변화(유료 생성·분석 공급자) — key 관리 강화.
3. 발행 플랫폼 REST 연동(법률 검토 후), 외부 도구 연동 사양 확인.
4. 영상 생성 파이프라인, React Flow 워크플로 빌더, 인증·RBAC, Postgres 전환.
5. S5 CMS/채널 커넥터 + 임베딩 유사도(Phase B).
6. S6 statsmodels/scikit-learn → LightGBM/시계열 DL 예측(Phase B/C, 라이선스 재검증).
7. S7 scikit-learn KMeans + silhouette/elbow, 딥 임베딩 군집 + 식별자 제안(Phase B/C, 개인정보 검토 후).
8. S8 실제 렌더 어댑터 + 경량 3D 구도 프리뷰 → 실제 3D 프리뷰(Phase B/C, 공급자·예산 확정 후).
9. S8 diff 재렌더 + **제작 유형별 실제 렌더/모션 내보내기**(플랫폼·엔진 확정 후, Phase B/C).
10. S8 유형별 기본 템플릿·비용 프로파일 확정, 자체 전문 지식베이스 확장(별도 관리 문서의 일반 원칙만 참조).
11. S8 레퍼런스 서치 실제 공개 API 어댑터 + 쿼터 예산 운영/우선 플랫폼 확정(Phase B), 타임코드 grounding 범위 검토 후 확장.
12. S8 실제 이미지/영상 변환·합성 어댑터(크롭·색보정·배경·객체·업스케일·스타일·트리밍·리타이밍·그레이딩·보간·레이어 합성) — **공급자·라이선스·예산 확정 후 Phase B/C 또는 제외**, 웹서비스형 처리 어댑터도 동일 기준.
13. S9 **공식 API 연동(Phase B)**: **사용자가 직접 로그인/OAuth로 연동한** 검색 콘솔 계정, 광고 계정의 공식 키워드 도구, 공식 검색 API. 인증·할당량·쿼터는 승인 후 운영, 스크래핑·우회 경로는 만들지 않는다. 실제 비용·비딩 실행은 매번 동의 + 임계값 초과 2차 확인 + 승인 이력 없이는 `CostApprovalService`가 거부한다.
14. S9 **회귀·예산 최적화(Phase B statsmodels/scikit-learn) → ML 최적화·포털 확장(Phase C)**. SERP 추적 출처 권리와 데이터 보유기간 확정 후 진행.

- [ ] **라우트가 10개(S0~S9)로 갱신되고 S9는 기본 "연결 안 함"으로 진입한다.**
- [ ] S0 수집 → F1~F7 순환이 Day 1~2 작업에 모두 매핑된다.
