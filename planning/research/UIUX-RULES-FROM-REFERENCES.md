# UIUX-RULES-FROM-REFERENCES — 레퍼런스 기반 UI·UX 규칙

> 저장소에 포함되지 않는 로컬 캡처 자료를 근거로 했으며, 이 문서는 경로에 의존하지 않는다.

작성일: 2026-11-22  
범위: 7개 레퍼런스 서비스의 텍스트·메타데이터·토큰 관찰에서 도출한 자체 UI·UX 규칙.  
전 규칙의 채택 분류: `UI·UX 패턴 참고 후 자체 구현`. 직접 코드·마크업·스크린샷 재사용은 0건이다.

---

## 1. 적용 원칙

| 항목 | 내용 |
|---|---|
| 채택 분류 | `UI·UX 패턴 참고 후 자체 구현` (관찰된 패턴을 근거로 삼되 산출물은 클린룸 재작성) |
| 근거 서술 | 모든 근거는 `캡처 분석 결과(로컬 전용, 저장소 미포함) — 관찰 요지` 형태의 일반 서술로 적는다 |
| 경로 의존 금지 | 구체 경로·파일명·링크·주소를 적지 않는다 |
| 시각 관찰 금지 | 이미지를 직접 열람하지 않았으므로 스크린샷을 보았다는 표현과 시각적 스타일 단정을 쓰지 않는다 |
| 약한 근거 | 관찰이 부분적이거나 오염 가능성이 있으면 `확인 필요`로 표시한다 |
| 규칙 우선순위 | 공식 플랫폼·디자인 시스템 가이드 > 검증된 레퍼런스 관찰 > 자체 디자인 결정 |
| 토큰 매핑 | 관찰된 수치와 이름은 그대로 옮기지 않고 자체 토큰명으로 환산한다 |

## 2. 서비스 코드

| 코드 | 서비스 | 주된 관찰 축 |
|---|---|---|
| SNIP | Snipit | 통합 수집·검색, 장문 탐색, 이름 없는 컨트롤 |
| BUF | Buffer | 폭·간격 체계, 발행 메시지, 스크립트 오류 |
| MONO | MONOV | 생성 변형, 이용 조건, 크레딧 상태, 오귀속 |
| CREA | Creatify | 입력 방식 분리, 모노스페이스 병기, 광폭 레이아웃 |
| MOTN | Motion | 리포팅 관점, 다단 폭 계층, 중복 랜드마크 |
| FORE | Foreplay | 소재 공유 워크플로, 분석 진입점, 좁은 폭 오버플로 |
| POSTZ | Postiz | 다채널 캘린더, 에이전트 보조, 상태 안정성 |
| CAN | 공통 | 중복 제거 후 자체 표준으로 승격한 규칙 |

규칙 ID는 `UXR-<서비스코드>-<세자리 번호>` 형식을 쓴다. 서비스별 규칙은 해당 서비스 관찰에서, `UXR-CAN-***`은 둘 이상의 서비스에서 반복되거나 자체 표준으로 승격이 필요한 관찰에서 부여한다.

## 5. 자체 토큰 매핑 대조

| 관찰 축 | 관찰된 형태 | 자체 토큰·컴포넌트 | 주의 |
|---|---|---|---|
| 배경·표면 | 밝은 계열과 어두운 계열 혼재 | `bg.app`, `surface.default`, `surface.subtle`, `surface.inverse` | 서비스 색상을 그대로 쓰지 않는다 |
| 텍스트 | 본문·보조·약화 3단 위계 반복 | `text.primary`, `text.secondary`, `text.muted` | 대비 기준은 자체 가이드를 따른다 |
| 강조·상태 | 브랜드색과 상태색 혼재 | `primary.500`, `success.500`, `warning.500`, `danger.500` | 의미별 토큰만 사용한다 |
| 글꼴 | 산세리프 계열 우세, 모노스페이스 병기 | `font.sans`, `font.mono` | 서비스 전용 글꼴은 가져오지 않는다 |
| 글자 크기 | 작은 본문 크기 다수 관찰 | `text.xs`부터 `text.xl` | 최소 크기 미달 관찰분은 승격하지 않는다 |
| 모서리 | 작은 값과 알약형 값 혼재 | `radius.sm`, `radius.md`, `radius.lg`, `radius.pill` | 네 종류로 제한한다 |
| 폭·간격 | 서비스별 상이한 최대폭과 간격 | `app grid`, `content max`, `gutter` | 세 토큰으로만 결정한다 |

`radius.md`는 중간 모서리 반경을 뜻하는 디자인 토큰 이름이며 문서 파일을 가리키지 않는다.

## 7. 적용 순서

1. 공통 규칙 `UXR-CAN-***`을 먼저 적용해 토큰·접근성·반응형 기준을 고정한다.
2. 서비스별 규칙은 해당 화면의 컴포넌트 명세와 1대1로 연결한다.
3. `확인 필요` 규칙은 근거가 보강될 때까지 설계 승인 게이트에서 보류한다.
4. 관찰된 수치는 자체 토큰으로 환산한 뒤에만 구현에 넘긴다.
5. 규칙 우선순위가 충돌하면 공식 가이드를 따르고, 판단 근거를 의사결정 기록부에 남긴다.
