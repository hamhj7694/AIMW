# COMPOSITION-PLAN — 레퍼런스 조합·점수화

작성일: 2026-11-22  
평가 대상: 7개 서비스 캡처 자료(로컬 분석 결과, 저장소 미포함)  
가중치(고정): **P0 적합성 30% / MVP 구현 가능성 25% / UI·UX 효율성 20% / 유지보수·확장성 15% / 연동·운영 비용 10%**  
점수 척도: 각 항목 0~5점(5=최고). 가중 합계 = Σ(항목점수 × 가중치), 최대 5.00.

> 평가 근거는 통합 감사와 기능 매트릭스의 감사 결과를 **로컬 캡처 분석 결과(저장소 미포함)를 일반 원칙으로 정리**한 것이다. 캡처는 이 저장소에 포함되지 않으므로 경로·파일명·링크·스크린샷 위치를 기재하지 않는다.
>
> **재캡처 반영**: 오귀속 자료는 여전히 제외하되, 로컬 캡처 분석 결과(저장소 미포함)에서 **Motion 진본이 확인**되어 Motion을 재평가했다(상세: 통합 감사의 Motion 재감사). 아래 점수는 30/25/20/15/10 가중치를 그대로 사용한다.
>
> **S8 추가 — 자체 설계(레퍼런스 점수 아님)**: S8 Video Workbench(제작 유형 6종 선택, 레퍼런스 서치, 2계층 분석, 4단계 게이트, 샷 단위 수정, 미디어 소스/변환/합성·권한 게이트·before/after·비용 미리보기)는 7개 캡처에 대응하는 기능이 없어 **아래 2장 점수표·순위에 넣지 않는다**. 제작 유형 체계, 레퍼런스 서치 체계, 미디어 변환·합성 체계 모두 자체 설계이며 점수·순위에 영향 없음. 전문 지식베이스는 공개 권위 자료로 **새로 저작**한 것으로 캡처 서비스의 증거가 아니다. 숏폼·모션그래픽 공식 스펙과 검색 축 근거도 이 새 자체 출처(별도 관리) 기반이다.
>
> **S9 추가 — 자체 설계(레퍼런스 점수 아님)**: S9 SEO & Search Growth(진단·키워드/콘텐츠·예산/예측·취합/개선)도 캡처에 대응하는 기능이 없어 **점수표·순위에 절대 포함하지 않는다**. **레퍼런스 자료에는 SEO 전용 캡처가 없다.** 따라서 SEO 기능은 캡처 점수 근거가 아니라 공개·공식 데이터 범위와 자체 설계 원칙으로만 정의한다.

## 3. 조합 결정 (Composition)

### 3-1. MVP에 즉시 조합하는 것 (UI·UX 패턴 참고 후 자체 구현)

| P0 단계 | 주 조합 | 보조 조합 | 조합 방식 |
|---|---|---|---|
| F1 레퍼런스 분석 | 검색 모드 세그먼트/보드 | 스와이프 파일·발견 필터 | 검색 모드 세그먼트 + 카드 그리드 + AI 추출 패널 |
| F2 콘텐츠 기획 | 4단계 소재 생성 흐름 | 리서치/에이전트 흐름 | 브리프 폼 → 콘셉트 3안 → 카피 |
| F3 콘텐츠 제작 | 사진→다수 결과 생성/편집/템플릿 | URL→영상/아바타 | 결과 그리드 + 프롬프트 패널, 실제 생성은 로컬/후속 API |
| F4 검수 | 사람 승인 문구 | 협업/승인 흐름 | 체크리스트 + 승인 게이트 |
| F5 발행 | 주간 캘린더/컴포저 | 채널·연결 카드 | 주간 그리드 + 채널 타일 + Dry-run |
| F6 성과 분석 | 지표 카드/Takeaways | 렌즈 비교 리포트 | 지표 카드 + 추이 차트 + Top 콘텐츠 표 |
| F7 개선 | 주간 Takeaways |Spyder 리포트 | 개선 카드 → 새 브리프 버튼(순환) |

**S0 수집은 위 표와 성격이 다르다.** 캡처에 수집 엔진이 없으므로 패턴 참고가 아니라 **자체 설계 + 검증된 오픈소스 라이브러리**로 조합한다.

| 단계 | 조합 | 채택 분류 | 방식 |
|---|---|---|---|
| S0-F1 수집 대상 등록 | 분야 키워드/우리 서비스/경쟁사 도메인 | 자체 설계 | 수집 대상 폼 + 수집 소스 모델 |
| S0-F2 파트별 수집 | 영상/이미지/블로그/뉴스 4탭 | 자체 설계 | 세로 탭(독립 URL) + 수집 어댑터 |
| S0-F3 소스 | 공식 영상/검색 API + RSS + 공개 뉴스 + 수동 | 공식 API·공개 피드(공식 API 한정) | 키/공개 피드만, 광고 라이브러리는 연동 대기 |
| S0-F4 정규화 | 피드 파서 + 본문 추출 + HTML 파서 | 직접 코드 재사용 아님(라이브러리 사용) | 중복 제거 + provenance 보존 |

**S5~S9도 캡처에 대응하는 기능이 없어 자체 설계다.** 캡처 점수표(2장)에는 반영하지 않고, 아래 조합 표로만 관리한다(점수 산정 사유 없음).

| 모듈 | 조합 | 채택 분류 | 연결 방식 |
|---|---|---|---|
| S5 우리 콘텐츠 허브 | 보관함 + 토큰 Jaccard 겹침 + 시리즈 + 백로그 | 자체 설계(그룹화 패턴 참고) | S0 결과는 "참고로 가져오기" 클릭 시 `ModuleLink` |
| S6 성과·예측 | 시계열 + 이동평균 baseline → statsmodels/scikit-learn → LightGBM/DL | 자체 설계(visual-first 리포트 패턴 참고) | "S5 콘텐츠와 연결" 클릭 시 `content_id` 참조 |
| S7 오디언스 세그먼트 | 전처리 + k-평균(k 3~6) + 프로필 | 자체 설계(그룹화/필터 패턴 참고) | "맞춤 콘텐츠" 클릭 시 `segment_id` 참조 |
| S8 비디오 워크벤치 | 제작 유형 6종 명시 선택 → 레퍼런스 서치 → 2계층 분석 → 용어 확인 → 콘티 → 3D 구도 스키마 → 애니매틱 → 단계별 렌더(샘플) + 샷 단위 수정 + **입력 소스 3종(`generate_new`/`transform_source`/`composite`) · 실제 사진/이미지/영상 변환·합성 스키마(이미지 6종·영상 7종·레이어/마스킹/블렌딩/타이밍) · 권한 게이트(`rights_flag`/`rights_confirmed_by`) · before/after · 샘플 단가 비용 미리보기** | 자체 설계(레퍼런스 점수 아님, S2와 독립, 자체 지식베이스 일반 원칙 참조) | S0는 "S8로 가져오기" 클릭 시 `ModuleLink(s0→s8)`, S2 참고는 `ModuleLink(s8→s2)` |
| S9 SEO & Search Growth | **진단(기술·온페이지·콘텐츠) → 키워드 갭·검색 의도 매핑 → 제목/메타/구조 개선안 → SERP 추적(공식 데이터 한정) → 투자비용↔성과 예측(CPC/CAC/ROAS/유입)·예산 배분 추천 → 취합 대시보드 → 개선 루프** | 자체 설계(레퍼런스 점수 아님, S6과 독립, 공개·공식 데이터 한정) | 기본 "연결 안 함", 개선 루프는 클릭 시에만 `ModuleLink(s9→s2)`/`ModuleLink(s9→s5)` |
| 모듈 연결 계약 | `ModuleLink(source, source_id, target, target_id, created_by)` | 자체 설계 | 사용자 클릭만, 자동 동기화 없음 |

> **엉킴 방지**: 위 여섯 모듈(S0/S5/S6/S7/S8/S9)은 서로 데이터를 복제하지 않고 위 계약으로만 연결된다. 다른 파트의 캡처 패턴을 억지로 섞지 않는다. S8의 제작 유형·레퍼런스 서치·미디어 변환/합성 체계와 S9의 SEO 체계도 자체 설계이며, 캡처 점수표·순위에 반영하지 않는다. **레퍼런스에는 SEO 전용 캡처가 없다.**

## 4. 단계별 채택 우선순위 (구현 순서와 정합)

1. **1순위 (Day 1 오전)**: 토큰/IA 패턴 → App Shell(10개 라우팅) + **S0 Collector 골격**(4 파트 탭, 수동/RSS 어댑터).
2. **2순위 (Day 1 오후)**: 공식 API 어댑터 1개 → 중복제거·이관 → S1 AI 분석(검색/보드 + 발견/스와이프 패턴).
3. **3순위 (Day 2 오전)**: 소재 생성 흐름 + 다수 결과 그리드 + 프롬프트 패턴 → S2 생성·검수.
4. **4순위 (Day 2 오후)**: 발행 캘린더 → S3 발행(Dry-run), 인사이트/Takeaways → S4 Insights + F7 순환.
5. **후속**: 광고 라이브러리 공식 심사 후 연동, 발행 플랫폼 실연동, 영상 생성, 워크플로 빌더.
6. **S8 (Phase A → B/C)**: 제작 유형 선택·레퍼런스 서치 스텁·샘플 게이트·미디어 소스/변환/합성 스키마·권한 게이트·before/after·비용 미리보기는 자체 설계로 먼저 확인하고, 실제 렌더/3D/diff 재렌더·유형별 모션 내보내기·실제 변환 어댑터·검색 API 쿼터 운영은 Phase B/C에서 공급자·라이선스·예산 확정 후 진행(미확정 시 제외). 점수표에는 반영하지 않는다.
7. **S9 (Phase A → B/C)**: 진단 룰 엔진·샘플 대시보드·예산 추천 시뮬레이션을 수동 입력/샘플로 먼저 확인하고, 공식 API 연동·회귀는 Phase B, ML 최적화·포털 확장은 Phase C. **점수표·순위에는 절대 반영하지 않는다.**

## 5. 민감도·리스크 메모

- 가중치가 **P0 적합성(30%) + MVP 구현(25%) = 55%**를 차지하므로, "F1~F7 직접 기여"와 "즉시 전환 가능성"이 순위를 지배한다. 이 때문에 Snipit·Buffer가 상위, Postiz는 연동 리스크로 하위가 됐다.
- MONOV는 F3 적합성 5점에도 생성 코드 품질/라이선스가 감점 요인(구현 3, 유지보수 3)으로 3위.
- Motion은 로컬 캡처 분석 결과(저장소 미포함)에서 **진본이 확인되어 3.70점으로 재편입**. 서비스 간 자료 혼동으로 잘못 분류되었을 뿐이며, 캡처 자체는 Motion 진본이다. 1~2일 MVP에는 전체 리포트가 아닌 "그룹화/태깅/모멘텀 카드" 패턴만 반영한다.
- 실제 발행/과금은 후속이며, **수집은 MVP에 포함되되 자체 파이프라인 + 공식/공개 소스에 한정**한다. MVP 점수는 "UI 패턴 재현 + 자체 수집 + 로컬 생성 + Dry-run" 기준이다.
- 7개 서비스 점수는 **캡처 자료의 기여도**만 평가한다. S0 Collector 및 신규 모듈(S5~S7, S8, S9)은 캡처에 근거가 없어 점수에 반영하지 않고 별도 조합 표로 관리한다. **점수 재산정은 Motion 1건뿐**이며, 이는 서비스 간 자료 혼동을 바로잡은 결과이지 가중치 변경은 아니다. S8 제작 유형 체계·레퍼런스 서치 체계·미디어 변환/합성 체계·전문 지식베이스, 그리고 **S9 SEO 체계는 모두 자체 설계/자체 저작이므로 캡처 점수·순위(현재 Motion 4위 3.70, Creatify 5위 3.55, Foreplay 6위, Postiz 7위)에 어떤 영향도 주지 않는다.**
- **레퍼런스에 SEO 전용 캡처가 없으므로** S9의 점수·순위를 산정하거나 기존 서비스 순위를 SEO 관점으로 재해석하지 않는다.
- **S8 권한 리스크**: 타사 미디어는 메타데이터 전용, 프레임 다운로드·분석 금지, `rights_flag`/`rights_confirmed_by` 미확인 시 잠금. 결과는 기존 4게이트를 그대로 통과한다.
- **S9 데이터 리스크**: 공식 데이터·공개 메타·수동 입력만 사용하고 스크래핑·로그인 우회·유료벽 우회를 금지한다. 예측에는 `예측/신뢰도/모델/샘플` 배지를 붙이고, S6 지표를 복제하지 않는다.
