# 13. SEO·검색 성장 (SEO & Search Growth)

S9 SEO & Search Growth 모듈의 도메인 근거. 공식 문서의 **원칙만 요약**하며 순위 보장을 약속하지 않는다.

> **중요**: Google 공식 가이드도 "특정 사이트가 구글에서 1위가 되도록 자동으로 해주는 비밀은 없다"고 명시한다(S23/A). 따라서 이 모듈의 목표는 **_search 엔진이 콘텐츠를 이해·색인·표시하도록 돕고, 유입·투자 효율을 측정·개선하는 것**이다. "최상위 노출 보장"은 **보장 불가**로 문서화한다.

## 13-1. 검색 엔진 기본

### KB-SEO-001 색인과 Discover/Crawl/Index
정의: 검색 엔진은 크롤러로 웹을 탐색해 페이지를 색인한다. 대부분의 사이트는 별도 등록 없이 자동 발견된다. `site:` 연산자로 색인 여부를 확인할 수 있다.
효과: "사이트를 등록해야 노출된다"는 오해를 막고, 진단의 첫 단계를 `색인 여부 확인`으로 둔다.
적용: `SeoDiagnosis.findings[]`의 `category=indexability` 첫 항목. Search Console 소유 확인 계정이 없으면 수동 `site:` 확인 결과를 `source_mode=manual`로 기록(Phase A).
주의: 색인된다고 검색 결과에 반드시 노출되는 것은 아니다.
근거: S23 / A

### KB-SEO-002 Search Essentials와 효과 발현 시점
정의: 검색 결과에 나타나기 위한 기본 요건(Search Essentials)을 지키면 노출 가능성이 높아진다. 변경 사항은 몇 시간~몇 달 뒤 반영될 수 있어, 보통 **몇 주** 관찰한 뒤 판단한다.
효과: "반영 안 됨"을 즉시 실패로 오인하지 않게 한다.
적용: `SeoRecommendation.expected_lag_weeks`에 `관찰 필요(수 주)` 기본값. 개선 루프의 재측정 시점을 최소 2~4주 뒤로 제안(C등급 경험치, 사용자 조정).
주의: 모든 변경이 measurable한 영향을 주지는 않는다.
근거: S23 / A

### KB-SEO-003 크롤러가 보는 페이지
정의: 크롤러가 사용자와 같은 리소스(CSS·JS)에 접근할 수 있어야 페이지를 이해한다. 중요 구성요소를 숨기면 이해·노출에 불리하다. 지역별 콘텐츠가 다르면 크롤러 위치(일반적으로 미국)에서 보는 내용도 확인한다.
효과: JS 렌더링 차단, 로그인 게이트, 지역 분기 같은 기술적 원인을 진단할 수 있다.
적용: 기술 진단 체크리스트 `crawler_visibility`. URL Inspection은 공식 도구로만, 계정 연동은 Phase B.
주의: 로그인/유료벽 우회는 이 프로젝트 범위 밖. 공개 범위만 진단.
근거: S23 / A, S24 / A

## 13-2. 온페이지·콘텐츠 규칙

### KB-SEO-004 제목 링크(Title link)
정의: 검색 결과의 제목은 `<title>` 요소와 페이지 내 헤딩 등에서 생성된다. 좋은 제목은 **페이지마다 고유**하고 명확하며 간결하고 내용을 정확히 설명한다. 사이트명·지역·핵심 정보를 포함할 수 있다.
효과: 사용자가 결과를 클릭할지 판단하는 첫 신호가 된다.
적용: `ContentOptimization.title_proposal` + `rationale`. 기존 제목은 `source_phrase`로 보존하고 제안은 별도 필드에 저장(자동 덮어쓰기 금지).
주의: 제목 길이 픽셀/글자 수 기준은 공식 고정값이 아니다. 특정 숫자를 단정하지 않는다.
근거: S23 / A

### KB-SEO-005 스니펫과 메타 디스크립션
정의: 스니펫은 페이지 실제 콘텐츠에서 주로 가져오며, 때때로 메타 디스크립션에서 가져온다. 좋은 메타 디스크립션은 짧고 페이지마다 고유하며 핵심 내용을 담는다.
효과: 메타 디스크립션을 "직접 쓴 문구가 그대로 노출된다"고 보장할 수는 없지만, 요약 품질을 높일 수 있다.
적용: `ContentOptimization.meta_description_proposal` + `source=actual_content|meta`. 노출 보장 배지 금지.
주의: 스니펫은 Google이 선택한다. 우리 도구가 확정하는 것이 아님을 UI에 명시.
근거: S23 / A

### KB-SEO-006 설명적 URL·주제별 디렉터리·중복 정리
정의: URL의 단어는 브레드크럼으로 표시될 수 있어 사용자 이해에 도움이 된다. 주제별 디렉터리는 대규모 사이트에서 크롤링 빈도 학습에 도움이 된다. 동일 콘텐츠가 여러 URL에 있으면 canonical 또는 리다이렉트로 하나의 대표 URL을 정한다.
효과: 구조적 중복으로 크롤링 예산이 낭비되는 것을 줄인다.
적용: `SeoDiagnosis.findings[].category=url|canonical`. canonical 적용 제안은 사용자가 검토 후 확정.
주의: 중복 콘텐츠는 스팸 위반이 아니며 구글이 자동 정규화하기도 한다. 과도한 경고 금지.
근거: S23 / A

### KB-SEO-007 유용한 콘텐츠와 피하지 말아야 할 관행
정의: 읽기 쉽고 구성이 좋으며 독창적이고 최신이며 사람 중심의 콘텐츠가 유리하다. 반면 **메타 키워드 태그는 사용하지 않고**, 키워드 스터핑은 스팸 정책에 위반된다. 콘텐츠 길이의 마법 숫자는 없고, E-E-A-T 자체는 순위 요소가 아니다.
효과: "글자 수 채우기", "키워드 반복", "메타 키워드 추가" 같은 유사 최적화를 배제한다.
적용: `ContentOptimization.checks[]`에 `keyword_stuffing`, `meta_keywords`, `word_count_target` 금지 항목 포함. 위반 시 감점이 아니라 "권장하지 않음"으로 표시.
주의: 헤딩 순서는 스크린리더 접근성에는 중요하지만 구글 순위엔 직접 영향이 없다는 공식 입장. 접근성 관점에서는 유지한다.
근거: S23 / A

### KB-SEO-008 이미지·영상 최적화
정의: 이미지는 관련 텍스트 근처에 두고, 선명하며, **설명적 alt 텍스트**를 붙인다. 영상은 독립 페이지에 임베드하고 제목·설명을 설명적으로 쓴다.
효과: 이미지/영상 검색을 통한 유입 가능성을 높이고 접근성도 개선된다.
적용: `ContentOptimization.alt_text_proposal`, `video_embed_check`. S8 산출물을 S9에 넣을 때도 사용자 클릭 `ModuleLink(s8→s9)`만.
주의: alt에 키워드를 나열하지 않는다(KB-SEO-007).
근거: S23 / A

## 13-3. 투자·성과 예측

### KB-SEO-009 Keyword Planner 예측의 입력과 출력
정의: Google Ads Keyword Planner는 입찰가·예산·계절성·과거 광고 품질을 반영해 노출·클릭·비용·CTR·평균 CPC를 **추정**한다. 과거 지표(월 평균 검색량 등)는 반올림되고 정확 일치 기준이며, 예측과 성격이 다르다. 상단 입찰가 범위는 약 20/80 백분위수 근사치다.
효과: "검색량 = 예상 트래픽"이라는 오해를 막는다.
적용: `SeoInvestment.forecast[]`에 `metric`, `value`, `method`, `is_forecast=true`, `source_id`. Phase A는 룰/샘플, Phase B에서 공식 데이터 연동.
주의: Keyword Planner 기본 기능 이용엔 계정 설정(결제 정보 입력)이 필요할 수 있다. **MVP에서 실제 계정 호출·과금은 하지 않는다.**
근거: S25 / A, S26 / A

### KB-SEO-010 예측 불일치 원인
정의: 예측과 실제가 다른 이유로 신규 계정(데이터 부족), 디스플레이 네트워크 포함 여부, 좁은 지역, 캠페인 간 유사 키워드 경쟁, 유사 키워드 간 트래픽 분할, 일주일 평균을 일별로 환산한 점 등이 공식 문서에 열거된다.
효과: 예측 오차를 "모델 실패"가 아니라 조건 차이로 설명한다.
적용: `SeoInvestment.deviation_notes[]`에 위 원인 체크리스트. 대시보드에 `예측/신뢰도/모델` 배지 상시 노출(NFR-14 연장).
주의: 원인을 단정하지 않고 후보로 제시.
근거: S26 / A

### KB-SEO-011 예산 배분과 취합·개선 루프
정의: 예측 지표(클릭·CPC·전환)와 실제 집행 결과를 키워드/채널/콘텐츠 단위로 취합해 차이를 보고, 다음 예산·콘텐츠·브리프를 갱신한다.
효과: S9가 일회성 진단이 아니라 **진단→예측→집행→취합→개선** 순환이 된다.
적용: `SeoRound` 엔티티에 `diagnosed_at`, `forecast`, `actual`, `delta`, `improvements[]`. 개선안을 S2 브리프/S5 콘텐츠로 보낼 때는 사용자 클릭 `ModuleLink(s9→s2|s5)`만. 자동 반영 금지.
주의: 광고 집행·예산 변경 실행은 MVP 범위 밖(Dry-run). 실제 전송은 Phase B/C에서 승인 후.
근거: 자체 설계(S23~S26 원칙 기반)

## 13-4. 데이터 출처 경계

| 소스 | 등급 | MVP 처리 |
|---|---|---|
| Google Search Console API | A | 소유 확인 계정만, Phase B 연동. MVP는 수동 입력/샘플 |
| Google Ads API / Keyword Planner | A | 결제 정보 설정 계정 필요. 과금·호출 없이 문서 근거만 사용 |
| 네이버 검색 API | A | 공개 검색 API 한정, 스크래핑 금지 |
| 공개 피드·메타, 수동 입력 | A/C | provenance 필수, 출처 불명은 C등급 |
| SERP 스크래핑·로그인 우회·유료벽 우회 | 제외 | 사용하지 않는다 |

> **포털 최상위 노출**은 목표 지표로 둘 수 있으나 **보장 결과로 약속하지 않는다**. 공식 문서 근거(S23/A)와 사용자 실제 데이터를 함께 제시하고, 모든 예측에 `예측` 배지를 붙인다.

## 13-5. 확정 운영 정책 (2026-11-22)

`DECISION-LOG.md` J-16~20 확정값: 소유 확인 계정만 사용(미확인 시 수동·샘플), 포털은 Google → 네이버 순, SERP는 공식/공개/수동만(스크래핑 금지), 보유기간은 Phase A 90일·Phase B 12개월(식별정보 미저장, 즉시 삭제 허용), S6 지표는 복제하지 않고 클릭 기반 참조. 순위 보장은 불가로 유지한다. 계정은 **사용자가 직접 로그인/OAuth로 연동**하고, 실제 비용·비딩·예산 변경은 **매번 명시 동의** 후 실행한다. 단일 10,000원 또는 월 누적 100,000원 초과 시 2차 확인 팝업, 기본 지출 상한 0원, 승인 이력(금액·항목·공급자·시각·승인자) 기록(DECISION-LOG J-27~29).
