## 1. 제품 개요

### 1-1. 비전
장기렌트 광고 운영을 위해 **레퍼런스 분석 → 기획 → 제작 → 검수 → 발행 → 성과 분석 → 개선**을 한 공간에서 잇는 AI 마케팅 운영 워크스페이스.

### 1-2. 문제 정의
- 레퍼런스 수집/정리가 흩어져 있고, 위닝 소재의 "왜 잘 먹히는가"가 기록되지 않는다.
- **관심 분야나 우리 서비스를 등록해도 경쟁사가 지금 어떤 콘텐츠를 내고 있는지 한곳에서 보기 어렵다.** 영상·이미지 광고, 블로그, 뉴스 보도가 서로 다른 채널에 흩어져 있다.
- 기획→제작→승인→발행이 도구 간 왕복으로 끊긴다.
- 발행 후 성과가 개선안으로 되돌아오지 않아 다음 캠페인이 매번 처음부터 시작된다.
- 생성형 AI 도구는 많으나 **출처·비용·승인 상태가 보이지 않아** 운영 신뢰가 낮다.
- **우리가 이미 만든 콘텐츠가 어디에 있는지, 어떤 내용과 겹치는지, 어떤 시리즈로 이어지는지가 정리되지 않아** 새 기획이 매번 처음부터 시작된다.
- **과거 성과를 이어서 보고 미래 성과를 예측하며, 고객/리드를 그룹별로 분류해 맞춤 콘텐츠를 뽑는 기능이 없다.**
- 위 기능을 한 화면에 몰아넣으면 오히려 복잡해진다. **모듈별로 독립적으로 쓰고, 필요할 때만 연결되는 구조**가 필요하다.

### 1-3. 제품 원칙
1. 결과물 중심 작업 공간 + SaaS 상태 밀도의 결합.
2. **캡처한 웹은 참고용이고, 수집·검색·분석 파이프라인은 이 프로젝트용으로 직접 설계·구현한다.**
3. AI 작업은 비동기 상태로 노출, 사람이 승인한다.
4. 출처·모델·비용·버전을 모든 결과물에 메타로 붙인다.
5. 수집은 공개 범위(공식 API·공개 피드·수동 입력)만 사용하고, ToS/robots/개인정보를 준수한다.
6. 발행/과금은 MVP에서 Dry-run, 실제 연동은 후속.
7. **모듈 독립성**: S0~S9 **10개 라우트**와 KnowledgeService(읽기 전용 공용 서비스, 라우트 아님)는 각자 데이터·상태를 가지며, 기본값은 "연결 안 함". 연결은 사용자가 명시적으로 선택할 때만 ID 참조로 발생한다.
8. 연결은 데이터 복제가 아니라 `content_id`, `segment_id` 같은 식별자 참조로만 이뤄진다. 한 모듈이 비어 있어도 다른 모듈은 샘플 데이터로 독립 사용 가능하다.

## 3. 범위

### 3-1. MVP In-Scope (1~2일)
- **S0 Collector (신규)**: 분야 키워드/우리 서비스 URL/경쟁사 도메인 등록 → 파트별(영상 광고 / 이미지 광고 / 블로그 / 뉴스) 수집·탐색·중복 제거 → S1 References 이관. 1차 소스는 YouTube Data API, 네이버 검색 API, RSS/Sitemap, GDELT, 수동 입력. 오픈소스는 `feedparser`, `trafilatura>=1.8`, `BeautifulSoup4/lxml` 사용.
- **S1 References**: 레퍼런스 저장/조회, 검색·필터, 보드, AI 분석(후킹/메시지/CTA/타깃).
- **S2 Studio**: 브리프 생성, 콘셉트 3안, 카피/프롬프트 생성, 4장 결과 그리드, 검수 체크리스트·승인.
- **S3 Publishing**: 채널 타일, 게시물 큐/주간 그리드, 채널별 변환 미리보기, 예약(**Dry-run**).
- **S4 Insights**: CSV 업로드·지표 매핑, 대시보드, 개선안 → 새 브리프.
- 공통: App Shell, JobDrawer, DetailPanel, 상태/토큰, 로컬 Ollama 추론.
- **S5 Own Content Hub (최소, 독립)**: 우리 과거 콘텐츠 보관함(수동/CSV 등록) → 기존 콘텐츠와의 겹침 플래그 → 시리즈/확장 태그 → 아이디어 백로그. S0 경쟁사 결과는 **"참고로 가져오기" 버튼을 누를 때만** 아이디어에 붙는다(자동 연결 아님).
- **S6 Performance & Forecast (샘플 뷰)**: S4와 별도 라우트. 과거 성과 추이 + 이동평균 기준 예측 미리보기. 실제 ML/DL 모델은 Phase B.
- **S7 Audience Segments (샘플 뷰)**: S6와 별도 라우트. 데이터/변수 선택 + k=3~6 군집 UI + 세그먼트 프로필 카드. 실제 KMeans 실행은 Phase B.
- **S8 Video Workbench (신규, 독립)**: S2와 별도 라우트. 분석 탭(내용 2계층 + 기술) / 제작 탭(자연어→용어 변환 → 콘티 → 3D 구도 → 애니매틱 → 단계별 렌더) / 수정 탭(샷 단위 타겟 패치). 입력 소스 모드는 `generate_new`/`transform_source`/`composite`이며, 실제 이미지·영상의 크롭·색보정·배경 교체·객체 편집·레이어 합성·마스킹을 지원한다(Phase A는 스키마·샘플·드라이런). **MVP에서는 텍스트·스키마·샘플 미리보기까지**를 만들고 실제 변환·렌더는 Phase B/C로 넘긴다.
- **S9 SEO & Search Growth (신규, 독립)**: S4·S6와 별도 라우트. 진단 / 키워드·콘텐츠 / 예산·예측 / 취합·개선 4탭. 기술·온페이지·콘텐츠 진단, 키워드 갭·검색 의도 매핑, 제목·메타·구조 개선안, SEO 투자비용↔성과 예측과 예산 배분 추천, 취합 대시보드와 개선 루프를 제공한다. 개선안을 S2/S5로 보내는 것도 **사용자 클릭 시 `ModuleLink`만** 생성한다. MVP는 수동 입력·샘플·룰 기반 예측·Dry-run이며 실제 계정 API 호출과 과금은 하지 않는다.

### 3-2. Out-of-Scope (명시적 제외)
- 실제 소셜 발행, 외부 API 결제, 30+ 채널 OAuth.
- **심사·신원확인·토큰이 필요한 광고 라이브러리 연동(Meta/TikTok/LinkedIn) — MVP에서는 "연동 대기"로 표시만.**
- **플랫폼 ToS가 금지하는 스크래핑(Meta/TikTok 등), 로그인/유료 영역 우회, 캡차·지문 위조·프록시 회전, 미디어(이미지·영상) 재호스팅.**
- Firecrawl 코어 self-host(AGPL), yt-dlp(저작권), Google News RSS(개인·비상업 전용), 유료 Apify Actor.
- 영상 생성(API 고비용), ComfyUI/Blender MCP, n8n 사용자용 워크플로 빌더.
- **영상 자동 전체 제작(요청 즉시 최종 렌더까지 일괄 실행)**: 비용·시간 절약을 위해 S8의 4단계 게이트를 강제한다. 사용자가 각 단계에서 "진행"을 누르지 않으면 다음 단계로 넘어가지 않는다.
- **타사 영상 프레임 다운로드·재호스팅·프레임 단위 복제**: 공개 메타/스냅샷 URL/타임코드 참조만 허용. 프레임 분석과 변환·합성은 사용자가 직접 업로드한 **자기 콘텐츠** 또는 권한을 확인한 소스에 한정한다.
- **권한 미확인 소스의 변환·합성 진행**: `rights_flag`/`rights_confirmed_by`가 없으면 G1 콘티 게이트로 넘어가지 않는다.
- **검색 결과 최상위 노출 보장 약속**: 공식 가이드도 순위를 보장하지 않는다. S9는 개선안·예측·측정치를 제공할 뿐 보장하지 않는다.
- **SERP 스크래핑·로그인 우회·유료벽 우회·무단 광고 계정 실행**: S9는 공식 API(사용자가 직접 연동한 소유 확인 계정)·공개 검색 API·수동 입력만 사용하고, 예산 변경·집행 실행은 Phase B/C에서도 매번 사용자 동의가 필요하다.
- **자동 결제·자동 비딩·자동 예산 변경**: 어느 단계에서도 금지한다. 실제 비용이 발생하는 동작은 금액과 무관하게 사전 동의를 받고, 임계값 초과 시 2차 확인 팝업을 띄운다.
- **시스템 주도의 계정 로그인·인증 대행**: 사용자가 직접 로그인/OAuth 승인하지 않은 계정으로 데이터를 조회하거나, 자격증명·토큰을 대신 입력·갱신·공유하지 않는다.
- 다중 사용자/권한, Postgres 전환, 모바일 전용 앱.
- **모듈 간 자동 연결/자동 동기화** (예: S0 수집 결과가 자동으로 S5에 들어가거나, S6 예측이 자동으로 S2 브리프를 만드는 것). 모든 연결은 사용자가 명시적으로 버튼을 눌러야 한다.
- **Phase B/C 알고리즘을 1~2일 MVP에 무리하게 포함하려는 시도** — KMeans/ML/DL 모델 학습, 외부 고객데이터 OAuth, 실시간 파이프라인은 MVP 범위 밖.
- 참고 대상 사이트의 코드·자산 복제, 출처 불일치가 확인된 자료군 사용. 진본으로 재분류된 자료군도 패턴 참고만 허용.
