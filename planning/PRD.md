# PRD — AIMW (AI Marketing Workspace) v1.0 / design-v3

> 상태: **기획 재정리 완료(2026-11-22) · 구현 착수 전**
> 이 문서는 v3의 **단일 현재 진실**입니다. 이전 개정 이력은 저장소 루트의 `CHANGELOG.md`로 이관했습니다.
> 설계 기준은 `design-v3/` 폴더로 완전히 이동했습니다. `planning/design/*`은 기록용 보관 문서이며 더 이상 구현 근거가 아닙니다.

---

## 1. 제품 한 줄

**업종에 묶이지 않는 마케팅 운영의 모든 단계 — 레퍼런스 수집, 기획, 제작, 검수, 발행, 성과, 개선 — 를 하나의 작업대에서, 사람이 확인하면서 진행하는 웹 워크스페이스.** 특정 산업·제품·브랜드의 사례를 UI 문구에 넣지 않습니다.

### 1-1. 우리가 solving 하는 문제

| 문제 | v3에서 어떻게 푸는가 |
|---|---|
| 경쟁사가 지금 내는 콘텐츠가 채널별로 흩어져 있음 | 한 곳에서 4개 채널(영상·이미지·블로그·뉴스)을 모아 보고, 출처와 함께 보관 |
| 기획→제작→승인→발행이 도구 왕복으로 끊김 | 하나의 작업대에서 단계가 보이고, 다음 할 일이 항상 하나 |
| 발행 성과가 다음 기획으로 돌아오지 않음 | 성과에서 개선안을 만들고, 클릭 한 번으로 다음 브리프에 담음 |
| AI 결과의 출처·비용·승인 상태가 보이지 않음 | 모든 결과에 "어디서/무엇으로/얼마에/누가 승인" 메타를 붙임 |
| 우리가 만든 콘텐츠가 어디 있는지 모르겠음 | 우리 콘텐츠 보관함에서 겹침·시리즈·아이디어를 관리 |
| 도구가 많을수록 무엇부터 해야 할지 모르겠음 | **홈 화면이 항상 "지금 할 일 하나"를 알려줌** |

### 1-2. 하지 않는 것 (Non-goals)

- 실제 소셜 발행, 자동 결제, 자동 비딩, 자동 예산 변경.
- 시스템이 대신 로그인하거나 토큰을 다루는 일.
- 플랫폼 ToS를 어기는 수집, 로그인/유료벽 우회, 타사 미디어 재호스팅.
- "클릭 한 번으로 최종 영상 완성" 같은 자동 전체 제작.
- 모듈 간 자동 연결·자동 동기화·데이터 복제.
- 순위 보장을 약속하는 SEO 결과.
- 2일 MVP에 Phase B/C 알고리즘(KMeans 회귀, 실제 렌더, 유료 API)을 억지로 담는 일.

## 2. 사용자

| 사용자 | 들어오는 이유 | 첫 화면에서 필요한 것 |
|---|---|---|
| 마케팅 운영자 | "요즘 경쟁사가 뭐 내놓지?" / "이번 캠페인 어디까지 왔지?" | 수집 현황 + 다음 승인/발행 할 일 |
| 크리에이티브 | "카피/이미지/영상 시안 빨리 보고 싶어" | 브리프 입력 + 결과 4장 + 재생성 |
| 팀 리드 | "승인할 것, 쓴 비용, 성과가 궁금해" | 검수 대기 + 비용 요약 + 성과 추이 |
| 콘텐츠 전략가 | "이 아이디어 이미 우리가 했던 거 아닌가?" | 우리 콘텐츠 보관함 + 겹침 표시 |
| 데이터/CRM 담당자 | "어떤 그룹에 뭘 팔아야 하지?" | 예측·세그먼트·SEO 개선안 |

**신규 사용자는 전문 용어를 모릅니다.** "제작 유형 6종"을 먼저 고르게 하지 않고, 하고 싶은 말을 문장으로 입력받은 뒤 시스템이 유형을 제안하고 사용자가 확정합니다.

## 3. v3 UX 원칙 (기존 11조를 7개로 압축)

1. **지금 할 일이 하나.** 모든 화면의 주 액션은 1개. 나머지는 보조로 처리.
2. **말로 시작하게 한다.** 비전문가 문장 → 시스템이 제안 → 사람이 확정. 전문 용어는 결과 화면에서 함께 배운다.
3. **모듈은 독립, 연결은 클릭.** 기본값은 "연결 안 함". `ModuleLink`는 사용자가 버튼을 누를 때만 생긴다.
4. **상태와 근거를 숨기지 않는다.** 진행/대기/완료/실패 + 출처·모델·예상 비용·승인자.
5. **시연은 시연답게.** 실제 발행·과금·렌더가 없는 동작에는 "시연" 배지를 상시 부착.
6. **빈 화면은 안내문이 아니라 다음 버튼.** "데이터 없음" 대신 "키워드 등록" 버튼을 보여준다.
7. **한국어로, 짧게, 긍정 문장으로.** 버튼은 결과가 보이게("승인하고 넘기기"), 오류는 원인과 해결을 함께.

## 4. 범위 — 지금 만드는 것 / 나중에 붙이는 것

| 구분 | 지금 (W0, 1~2일) | 나중 (W1~W3) |
|---|---|---|
| 워크스페이스 | 앱 셸, 5개 작업 공간, 10개 모듈 골격 | 모듈별 심화 |
| 수집 | S0 4채널 수집/탐색 + 중복 제거 + 출처 보존 | 공식 커넥터, 임베딩 유사도 |
| 참고/자산 | S1 보드·분석, S5 보관함·겹침 플래그 | CMS 연동 |
| 기획/제작 | S2 브리프→콘셉트→결과 4장, S8 자연어→용어→4게이트 샘플 | 실제 이미지/영상 변환·렌더 |
| 발행/성과 | S3 채널 미리보기·예약(시연), S4 CSV 대시보드, S6 이동평균 예측 뷰, S7 세그먼트 UI(샘플) | 실제 API 연동, KMeans/회귀 |
| 성장 | S9 4탭 룰 기반 진단·예산 시뮬레이션(샘플) | 공식 계정 데이터, ML 최적화 |
| 거버넌스 | 비용 승인 게이트(스펙), 권한 확인, KB 인용 | 실제 과금/집행 연결 |

> W0의 성공은 "10개 화면이 다 채워진 것"이 아니라 **"한 캠페인을 수집→기획→제작→검수→발행(시연)→성과까지 클릭으로 완주한 것"**입니다. 나머지 모듈은 빈 상태/샘플 상태로도 독립 진입 가능해야 합니다.

사이드바는 사용자가 이해하는 이름을 쓰고, 괄호 안에 기존 모듈 ID를 유지합니다. (기존 ID_order 불일치 해소)

| 작업 공간 | 포함 모듈 | 한 줄 설명 |

| 살펴보기 | S0 Collector · S1 References · S5 Own Content | 경쟁사/레퍼런스/우리 콘텐츠 |

| 발행 | S3 Publishing | 채널 미리보기, 게시 큐(시연) |

## 6. 핵심 여정 (자세한 화면 흐름은 `JOURNEYS-V3.md`)

### 6-1. 첫 캠페인 (주 흐름)

```
홈 → 키워드 등록 → 수집 결과 확인 → 레퍼런스 3개 저장 → "이걸로 브리프"
  → 콘셉트 1개 선택 → 결과 4장 → 검수 체크 → "승인하고 큐에 넣기"
  → 발행 예약(시연) → 성과 CSV 업로드 → "개선안 브리프로 보내기" → 홈
```

### 6-2. 영상 요청 (비전문가 친화)

```
요청 문장 입력
  → 시스템이 표준 용어 매핑표 + 추천 유형 3안 제시
  → 사용자가 해석 확정 (신뢰도 낮으면 되묻기)
  → (선택) 레퍼런스/내 소스 첨부 + 권한 확인
  → [G1 콘티] → [G2 구도] → [G3 애니매틱] → [G4 샷별 렌더(시연)]
     각 게이트마다 미리보기 + 예상 비용/시간 + "진행" 버튼
```

### 6-3. 독립 모듈 (연결 0건이 정상)

- 우리 콘텐츠 보관함: 등록 → 겹침 표시 → 시리즈 지정 → 아이디어 백로그.
- 성과·예측: 샘플 데이터 → 기간 선택 → 예측 밴드(신뢰도/모델 배지).
- 오디언스: 변수 선택 → k 선택 → 프로필 카드.
- SEO: 진단 → 키워드 갭 → 예산 시뮬레이션 → 개선안.

각 모듈은 다른 모듈이 비어 있어도 진입 가능하며, 이동은 항상 사용자의 명시적 클릭으로만 발생합니다.

## 8. 불변 제약 (v3에서도 그대로)

1. 직접 코드·마크업·스크린샷 재사용 0건, 로컬 전용 자료 경로 의존 0건.
2. 10개 모듈 + KnowledgeService. 기본 "연결 안 함", `ModuleLink`만 연결, 데이터 복제 금지.
3. 발행·과금·렌더는 W0에서 Dry-run. "시연" 배지 상시.
4. 계정 로그인/OAuth는 사용자가 직접. 자격증명 대리 입력 금지.
5. 실제 비용 발생은 매번 동의. 단일 10,000원·월 100,000원 초과 시 2차 확인, 기본 상한 0원, 승인 이력 기록.
6. S8은 4게이트 강제. 사용자의 "진행" 클릭 없이 다음 단계 생성 0건. 제작 유형은 추천 후 확정.
7. 미디어 권한(`rights_flag`/`rights_confirmed_by`) 미확인 소스 변환 0건. 타사 프레임 재호스팅 0건.
8. S9는 공식·공개·수동 데이터만. 모든 예측에 `예측/신뢰도/모델/기간` 배지, 순위 보장 문구 0건.
9. KB 근거 등급 A/B/C, C는 "검증 필요" 배지, 2문장 이상 연속 재현 금지.
10. 참고 서비스 점수·순위 불변. 자체 설계 모듈은 점수표에 포함하지 않음.

## 10. 용어 (화면에 그대로 쓰는 말)

| 화면 문구 | 의미 | 쓰지 않는 말 |
|---|---|---|
| 다음 할 일 | 사용자가 지금 해야 할 단 하나의 행동 | AI 추천 액션, Next Best Action |
| 시연 | 실제 외부 전송/과금이 없는 동작 | Dry-run, 스텁 |
| 샘플 | 실제 데이터가 아닌 예시 값 | Mock, Fake |
| 검증 필요 | 근거 등급 C 또는 신뢰도 낮음 | 불확실, 미정 |
| 승인하고 넘기기 | 검수 통과 후 다음 단계로 이동 | Submit, Confirm |
| 브리프 | 제작 요청서 | Brief(괄호 없이 단독 사용 금지) |
| 샷 | 영상의 최소 수정 단위 | shot_id(화면에 노출 금지) |

## 11. 변경 게이트

- 제품 방향 변경 → 이 문서를 먼저 수정하고 `CHANGELOG.md`에 한 줄 기록.
