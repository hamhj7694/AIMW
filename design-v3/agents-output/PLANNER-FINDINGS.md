## 1. IA 확정 — 홈 → 프로젝트 선택 → 각 상세 화면

```
[홈]  큰 배너 + 주 버튼 1개 + AI 입력(실행 방식 드롭다운 + API 키 입력)
  │   사용자가 [프로젝트 열기]를 클릭할 때만 이동
  ▼
[프로젝트 선택]  프로젝트만 나열. 각 행의 [열기]를 클릭할 때만 이동
  │
  ├─ [살펴보기]   출처와 함께 소스 저장 → [참고로 보내기] 클릭 시에만 다음 값 전달
  ├─ [스튜디오]   브리프 → 콘셉트 확정 → 결과 → 검수
  ├─ [영상 워크벤치] 자연어 요청 → 해석 확정 → 4단계 확인
  ├─ [발행]       승인 결과 예약 (시연 · 실제 전송 없음)
  ├─ [성과]       지표/예측/오디언스 → [개선안 브리프로 보내기]
  ├─ [성장]       진단/키워드/예산/개선 → [개선안 브리프로 보내기]
  └─ [설정]       실행 방식 · 모델 · API 키 · 비용 확인/한도
```

**이동 규칙 (불변)**
- 화면 간 이동은 **사용자 클릭으로만** 발생합니다. 자동 이동·자동 값 전달·자동 상태 동기화는 0건입니다. (PRD 원칙 3, 불변 2, JOURNEYS 25행)
- 모든 화면의 주 액션은 1개입니다. 나머지는 텍스트 링크로 강등합니다. (PRD 원칙 1)
- "다음 할 일"은 화면마다 **정확히 1개**이고, 없으면 `여기까지 완료`라고 씁니다. (JOURNEYS 원칙)
- v7의 좌측 레일·상단 프로젝트 컨텍스트·우측 패널·하단 상태바 구조는 **참고하지 않습니다.** 레이아웃은 디자이너가 0에서 다시 결정합니다. (U-01, U-07)

## 2. 화면 역할 문장 — 한 줄 정의 + 역할에 없는 문구 지적

| 화면 | 역할 문장 (한 줄) | 역할에 없는데 현재 들어 있는 문구 (지적) |
|---|---|---|
| 홈 | 지금 확인할 일 하나와 AI 요청入口를 보여 준다 | `현재 상태: 검토 대기`(개발자 라벨), `다음 작업`+`다음 할 일` 2회 반복, 마케팅 문체 설명문 |
| 프로젝트 선택 | 어느 프로젝트에서 시작할지 사용자가 직접 고른다 | 프로젝트 행마다 붙은 작업 이름과 `현재 상태`(출처 확인·콘셉트 검토…) |
| 살펴보기 | 외부 소스를 출처와 함께 사용자의 판단에 올린다 | 채널별 `대기`, 결과별 `검토 중`, 행마다 반복되는 `출처 메타 보존` |
| 스튜디오 | 콘셉트를 사람이 확정한 뒤 결과를 만든다 | `선택 대기`(행동이 아닌 상태 라벨), 의미 없는 `첫 번째 방향` 류 설명 |
| 영상 워크벤치 | 자연어 요청을 해석·확정하고 4단계를 사람이 확인한다 | `확인 전` 4회 반복, `G1~G4` 내부식 코드 라벨 |
| 발행 | 승인 결과를 시연으로 예약하고 외부 전송이 없음을 알린다 | `계정 확인됨` / `계정 확인 필요`(연결 상태의 변형), `시연` 4회 반복 |
| 성과 | 숫자와 예측의 신뢰도를 함께 읽게 한다 | `입력 대기` 3회, 행마다 `확인` 버튼 3개, 주 버튼 2개 |
| 성장 | 개선안과 근거를 함께 보여 주고 순위 약속을 막는다 | `제안 대기`, 개발자 용어 `룰 기반입니다`, 순위 문구 2회 반복 |
| 설정 | 실행 방식·모델·키·비용 통제를 한 곳에 둔다 | `선택`(placeholder 옵션), 당연한 마스킹 안내, 중복 드롭다운 2개 |

> 역할 문장 자체는 06감사 2절의 8개 문장을 9화면으로 확장하고, v7에서 새로 생긴 "프로젝트 선택"을 추가한 것입니다.
> 각 역할에 **없는** 문구를 지적하는 것이지, 역할을 바꾸자는 제안이 아닙니다.

## 3. 화면별 대안 — 현재 평가 / 문제 / 실제 화면 문자열 / 레이아웃 / 근거

### 3-2. 프로젝트 선택

| 화면 | 현재 역할 평가 | 문제점 | 대안 카피 문자열(화면에 들어갈 문구 그대로) | 레이아웃·계층 의견 | 근거 |
|---|---|---|---|---|---|
| 프로젝트 선택 · 제목 | 역할(직접 고름)에는 맞음 | 부제가 틀린 대상을 가리킴 | 제목: `프로젝트 선택`<br>부제: `어느 프로젝트에서 시작할지 고릅니다.` | 제목 한 줄, 부제는 13px 한 줄. 같은 영역에 버튼 붙이지 않기 | U-02, PRD FR-01 |

## 9. 2차 검토 예약 — 디자이너 반영표를 기다립니다

디자이너가 `v8` 초안과 `DESIGNER-FINDINGS.md`의 **"기획 의견 반영표"**를 만드는 대로, 이 파일에 **"2차 검토"** 섹션을 추가하겠습니다.

**반영표에 담아 주면 좋은 열 (제안):**
`제안 ID(3-1~3-9, 4절, 5절)` / `채택·부분반영·미반영` / `실제로 넣은 문자열(그대로)` / `화면 위치` / `수용·반박 근거`

**2차 검토에서 특히 다시 보는 항목 (재검토 트리거):**

| 검토 축 | 재검토 요청 조건 | 근거 |
|---|---|---|
| U-02 계열 | "모듈"/"한 화면에서"가 부분반영으로라도 남거나, 프로젝트 선택에 작업 열이 있으면 | 원 지적 직결. 부분반영도 재검토 요청 |
| U-05 계열 | 연결 상태가 한 곳이라도 남거나, 불변 규칙 문구(시연·승인 전·검증 필요·순위)까지 같이 지워지면 | SURVEY V8·V9 동시 실패 |
