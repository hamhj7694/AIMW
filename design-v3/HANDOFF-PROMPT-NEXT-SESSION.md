### 2. 작업 범위

- **기존 디자인을 유지한 채 부분 업데이트/개선**만 한다. 사용자가 이 파일이 더 예쁘다고 판정했다.
- 기존 화면 구조와 시각 문법을 살리고, 아래 항목만 고친다.
- 홈은 큰 배너 + 명확한 버튼 + AI 채팅 입력 구조를 유지한다. AI 입력은 모델 선택(로컬/API)과 API 키 직접 입력을 보이는 라벨과 함께 유지한다. 키 자동 채우기·기억하기 UI는 넣지 않는다.
- 기능 진입은 프로젝트 분류 → 상세 순서를 유지한다.

### 3. 제거할 문구/UI (사용자 지적 사항)

아래가 화면에 있으면 전부 제거하거나 자연스러운 기능 문구로 바꾼다:

- 개발자용 연결 상태: `연결됨`, `연결 안 됨`, `자동 연결`, `AI 연결`
- 미구현 워딩: `프로젝트와 모듈을 한 화면에서 시작`, `한 화면에서`, `로드맵`, `향후 고도화`
- 내부 식별자: `모듈`, `S0`~`S9`, `G1`~`G4`
- Anti-Slop: 업종명·제품명·브랜드명·상황 묘사, `예:` 힌트, 데모용 가짜 수치, 인사말 카피

### 4. 유지할 제품 불변 규칙

자연스러운 한국어로 유지한다:

- 시연 화면이며 실제 전송과 결제는 일어나지 않는다
- 실제 비용이 드는 요청은 매번 확인받은 뒤에만 진행한다
- KB 근거 A/B/C
- 4게이트(콘티/구도/애니매틱/샷 확인)는 직접 확인한 뒤에만 넘어간다
- 순위를 보장하지 않는다
- 연동은 계정 소유자가 직접 한다

### 5. 협업 방식

- 기획자 에이전트가 UIUX와 카피에 적극적으로 의견을 내고, 디자이너는 그 의견을 논의한 뒤 반영 여부를 명시한다.
- 산출 문서에 **기획 의견 반영표**(제안 / 반영 결정 / 실제 화면 문구 / 근거)를 적는다.
- 모든 보고와 UI 카피는 자연스러운 한국어로 작성한다.

### 6. 검증과 완료 기준

- 대비 4.5:1 미달 0건, 잘림 0곳, 이름 없는 컨트롤 0건, 금지 문구 0건을 실측한다.
- 자동 검사 통과를 최종 합격으로 보지 않는다. **사용자 육안 확인 게이트**를 통과해야 완료다.
- Figma MCP나 Code Layer 업로드가 막히면 추측하지 말고 막힌 이유를 보고하고 대안을 제안한다.
- 작업이 끝나면 변경사항을 `design-v3` 브랜치에 커밋·푸시한다. 숫자를 임의로 조정하지 마라.
