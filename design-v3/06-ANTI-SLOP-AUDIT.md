# 06 — Anti-Slop 자기 감사 v3.1

> GitHub에서 내려받은 스킬의 체크리스트를 한국어로 옮겨 화면마다 적용한 결과입니다. 원문은 `skills/`에 보관했습니다. 스킬의 미학 예시는 쓰지 않고 판단 기준만 사용했습니다.

---

## 1. 적용한 규칙 출처

| 스킬 | 가져온 판단 기준 |
|---|---|
| `anti-slop-design` | 색 3개와 60/30/10, 순수 흰/검 금지, Inter 금지, 3카드 그리드와 벤토 금지, 구조는 선과 타이포로 |
| `deslop` | 화면 역할 문장, 회색 와이어프레임 먼저, 구현 후 재감사, "이 화면이 없으면 무엇이 안 되는가" 질문 |
| `figma-designer` | 폰트 런타임 프로브, 변수 바인딩, Auto Layout, 계층형 이름, 컴포넌트 상태 |
| `anti-ai-ui` | 슬롭 UI 패턴 목록, 대시보드 카드 남발 경계 |
| 내장 `frontend-design` | 2패스 자기 비평, 현재 AI 디자인 클러스터(크림+세리프 대제목+테라코타, 얇은 선 과잉) 회피 |

## 2. 화면 역할 문장 (deslop 1단계)

| 화면 | 역할 문장 | 없으면 안 되는 이유 |
|---|---|---|
| S0 홈 | 지금 확인해야 할 일 하나와 그 근거를 보여 준다 | 다음 행동을 찾는 시간을 줄이려고 |
| S1 살펴보기 | 외부 소스를 사용자의 판단에 올린다 | 레퍼런스 없이 브리프를 쓰지 않게 하려고 |
| S2 스튜디오 | 콘셉트를 사람이 확정한다 | 자동 생성 결과를 그대로 쓰지 않게 하려고 |
| S3 영상 | 자연어 요청을 4게이트로 검증한다 | 게이트를 건너뛰지 않게 하려고 |
| S4 발행 | 승인 결과를 예약하되 실제 발행을 하지 않는다 | 시연 경계를 분명히 하려고 |
| S5 성과 | 숫자와 예측의 신뢰도를 함께 읽게 한다 | 예측을 확정으로 오해하지 않게 하려고 |
| S6 성장 | 개선안과 근거를 함께 보여 준다 | 순위 보장 약속을 막으려고 |
| S7 설정 | 연결과 비용 통제를 한 곳에 둔다 | 자동 연결과 자동 과금을 막으려고 |

## 3. 슬롭 신호 → 이번 안의 처리

| 신호 | 직전 안 | 이번 안 |
|---|---|---|
| 파란 SaaS 팔레트 | v3.0 페트롤+틸 | 제거, 복사지+먹+도장 3색 |
| 색 5개 이상 | danger/success/attention/teal/amber | 신호색 1개, 상태는 글자 |
| 크림+세리프 대제목+테라코타 | 1차 재설계 안 | 배경을 차가운 회색으로, 세리프는 숫자 도장만 |
| 3개 동일 카드 그리드 | 콘셉트 카드 | 작업 행 3줄 |
| 4개 지표 카드 | 성과 카드 | 수치 띠 한 줄 |
| 둥근 카드와 그림자 | radius 8~20, shadow 2종 | radius 0~2, shadow 없음 |
| 점 그리드 캔버스 | 24px 배경 | 제거 |
| 알약 배지 남발 | 6종 배지 | 텍스트 스탬프, 화면당 최대 2개 |
| 가운데점 메타 문자열 | `시연 · 실제 발행 없음` | `시연 화면입니다. 실제 발행은 일어나지 않아요.` |
| 화살표가 붙은 버튼 | `상세 작업 열기 →` | `작업 열기` |
| 스피너와 스켈레톤 | 일부 상태 | 숫자와 2px 선 |
| 이모지 아이콘 | 없음 | 유지 0개 |
| 그라데이션 미리보기 썸네일 | 있음 | `ink` 면 + 텍스트 라벨 |
| 장식 애니메이션 | 없음 | 유지 0개, 진입 opacity 120ms만 |

## 4. 2초 테스트

화면을 2초 보고 대답해야 하는 질문: **"지금 뭘 하면 되나?"**

| 화면 | 2초 답 |
|---|---|
| 홈 | 결과 확인 |
| 수집 | 수집 시작 |
| 스튜디오 | 콘셉트 선택 후 결과 만들기 |
| 영상 | 현재 게이트의 다음 단계 진행 |
| 발행 | 승인하고 큐에 넣기 |
| 성과 | 개선안 브리프로 보내기 |
| 성장 | 개선안 적용 |
| 설정 | 한도 저장 또는 연결 확인 |

주 액션이 2개 이상으로 보이면 실패입니다. 플러그인이 `Button/Action` 인스턴스 수로 검사합니다.

## 5. 최종 자기 비평

- **1패스:** 규칙을 너무 충실히 따라 크림 종이, 세리프 대제목, 테라코타 도장을 썼습니다. `frontend-design`의 현재 AI 클러스터 진단에 걸렸습니다.
- **2패스:** 배경을 차가운 복사지로 바꾸고, 세리프를 숫자 도장으로만 제한했습니다. 섹션 번호는 실제 게이트 순서에만 남겼습니다. 상태 문자열의 가운데점을 제거했습니다. 카드를 모두 행으로 바꿨습니다.
- **남은 위험:** 1px 규칙선도 남용하면 또 다른 전형이 될 수 있습니다. sections은 화면당 3개 이하로 제한했습니다.
- **사람 게이트:** 전체 화면 캡처를 보고 "광고 대시보드가 아니라 작업 지시서처럼 보인다"고 말할 수 있을 때만 합격입니다.

## 6. 자동 검증과 사람 검증의 분리

| 자동 검증 | 통과 기준 |
|---|---|
| 프레임 넘침 | 0 |
| 미바인딩 fill | 0 |
| 화면당 주 액션 | 1 |
| 하드코딩 hex(토큰 보드 제외) | 0 |
| 폰트 프로브 | 설치된 폰트로 fallback 보고 |

| 사람 검증 | 기준 |
|---|---|
| 시각 합격 | 작업 지시서로 읽힘 |
| 한글 잘림 | 0 |
| 색 균형 | 신호색이 튀지 않음 |
| 카피 | 자연스러운 한국어, 가운데점 없음 |
| 접근성 | 키보드 주행 완주 |
