# 04 — Figma 플러그인 가이드

## 왜 플러그인인가

이 환경에는 Figma MCP도, 컴퓨터 유즈(화면 조작) 도구도 없습니다. 대신 **Figma Plugin API를 사용하는 제너레이터**를 만들었습니다. 새 디자인을 제안하는 AI가 아니라, `00~03` 문서에 확정된 값을 기계적으로 옮기는 실행자입니다.

## 흐름

```text
design-v3/00~03 문서 (사람이 확정)
        ↓ 값 동기화
figma-plugin/code.js 상수
        ↓ 실행
Figma 3페이지 (토큰 → 컴포넌트 → 화면 → 검증 → 핸드오프)
        ↓ 사람 게이트
육안 검수 → 합격 / 반려
```

## 설치·실행

1. Figma 파일 열기 → Plugins → Development → **Import plugin from manifest…**
2. `design-v3/figma-plugin/manifest.json` 선택
3. 플러그인 실행 → **디자인 생성**

## 연결에 사용한 규칙

| 원칙 | 적용 |
|---|---|
| 문서가 단일 진실 | 플러그인은 값을 제안하지 않고 상수만 읽음 |
| 3색 원칙 | `paper`, `ink`, `signal` + 명도 파생 4개만 변수로 만듦 |
| Anti-slop 구조 | 카드, 그림자, 알약 배지, 점 그리드, 그라데이션을 생성하지 않음 |
| 토큰 없이 화면 금지 | `buildTokens()` → `buildTextStyles()` → 보드 → 컴포넌트 → 화면 순서 |
| 색은 변수에 바인딩 | 모든 `fills`에 `setBoundVariable()` 호출, 미바인딩 0 보고 |
| Auto Layout + 계층형 이름 | `Button/Action`, `Row/Task`. `Frame 123` 금지 |
| 폰트 런타임 프로브 | `listAvailableFontsAsync()`로 한국어 산세리프·세리프 확인 후 로드 |
| 게이트 카운트 | 화면마다 `Button/Action` 인스턴스가 정확히 1개인지 검사 |
| 넘침 감사 | 프레임 생성 직후 직계 자식 경계 비교 → 0 |
| Starter 제약 | 페이지 3개 고정, 모드 1개 컬렉션 여러 개 사용 |
| 보고 형식 | UI에 "만든 것 / 검증 숫자 / 다음" 표시 |

## 채택하지 않은 것

- cinemokhwa의 목화/먹색 팔레트, 필름 그레인, 세리프 대제목, 프로젝트 톤.
- v3.0의 페트롤+틸+앰버 팔레트와 32색 토큰.
- v3.1 1차 안의 크림+세리프 제목+테라코타 조합.
- "숫자 PASS = 디자인 PASS"라는 착각.

## 알려진 제약

- `figma.variables.setVariableAlias` API가 버전에 따라 다를 수 있어, 실패 시 원시값으로 대체하고 경고를 띄웁니다.
- Pretendard와 나눔명조가 없는 환경에서는 설치된 한국어 폰트로 폴백하며 UI에 보고합니다.
- 실제 썸네일 이미지는 저장소에 없으므로 `ink` 면에 텍스트 라벨로 표시합니다.
- 플러그인은 텍스트와 도형만 생성합니다. 인터랙션 프로토타이핑은 사람이 연결해야 합니다.
- 재생성 시 변수와 페이지는 재사용하지만 노드가 중첩될 수 있습니다. 대상 페이지를 비우고 실행하세요.
