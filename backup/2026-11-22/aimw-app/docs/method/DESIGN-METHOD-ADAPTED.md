## 3. 확인이 필요한 충돌 3가지

### 3-1. "디자인 계획안이 단일 진실" vs 새 컨셉
- 공식 규칙: 디자인 계획안의 색·화면·카피만 쓴다.
- 현실: 승인된 `DESIGN-PLAN.md`는 `Creative Operations Studio`(primary `#3159D9`)인데, 사용자가 요구한 "완전 새로"로 만든 `CONCEPT.md`는 `라이트테이블`(mark `#C8402F`)이다. 팔레트가 다르다.
- **선택지 A (권장)**: `CONCEPT.md`를 `aimw-design/DESIGN-PLAN-v2.md`로 승격해 단일 진실로 삼고, 이후 모든 단계가 이 문서만 따른다. 기획 저장소는 건드리지 않는다.
- **선택지 B**: 승인된 기존 `DESIGN-PLAN.md` 토큰으로 되돌리고 라이트테이블은 폐기.
- **선택지 C**: 두 문서를 병합한 v3를 새로 승인.

### 3-2. 도구 모드
- Figma MCP / 컴퓨터 유즈 모두 이 세션에 없다.
- 사용 가능: `browser.*` (페이지 열기·스크린샷·검사), 파일 쓰기, `browser.preview`.
- **대안**: 디자인 보드(`index.html`)를 1차 산출물로 쓰고, Figma로 옮길 구조는 `figma/components.svg` + `figma/HANDOFF.md`로 고정한다. 실제 Figma 파일 생성은 연결 후 단계로 분리한다.

### 3-3. 공식의 검증 규칙과 도메인 요구의 충돌
| 공식 규칙 | AIMW 요구 | 조정안 |
|---|---|---|
| 화면당 80단어 초과 금지 | 모든 결과물에 출처·모델·비용·게이트 메타 상시 노출 (DESIGN-PLAN 원칙 5) | **서술문 80단어**로 한정. 메타 라벨:값은 예외 |
| 정보 6줄 초과 금지 | 검상 패널에 출처/권리/비용/게이트가 기본 6줄 이상 | 라벨:값 1줄은 정보 1개로 계산 |
| Semantic Color(다크) → Light 별도 | 라이트 단일 모드. 다크는 로그/미리보기 패널 한정 | 다크全文 모드 제거, `surface.inverse`만 유지 |
| 컴포넌트 20~25개 | `COMPONENT-SPECS.md`에 primitives 14 + domain 60+ + layout 6 + composite 10 | 전체 인벤토리를 등록하되 **핵심 10개**를 1차 구현 대상으로 지정 |

## 4. 실행 프롬프트 (치환 완료)

```text
[역할]
너는 "디자인 공식"을 실행하는 시니어 프로덕트 디자너다.
목표는 특정 스타일 복제가 아니라 문서 → 계획 → 토큰 → 컴포넌트 → 화면 → 검증 → 핸드오프 공식을
AIMW에 그대로 적용하는 것이다.

[대상]
- 프로젝트: AIMW — AI Marketing AX Workspace
- PRD: ...\planning\PRD.md (v0.6)
- 디자인 계획안: 3-1 결정 결과를 따른다 (미결정 시 만들지 말고 질문)
- Figma 파일: 없음 (연결 대기)
- 실행 도구: 브라우저 디자인 보드 + SVG 핸드오프
- 기준 해상도: 1440×900

[불변 규칙]
1. 디자인 계획안이 단일 진실이다. 다른 프로젝트의 색·화면·카피를 가져오지 않는다.
2. 토큰 없이 화면을 만들지 않는다. hex 하드코딩 금지.
3. 컴포넌트 없이 화면을 만들지 않는다. 같은 요소를 두 번 만들지 않는다.
4. 프레임 생성 직후 넘침을 수치로 감사하고 0으로 만든다.
5. 각 단계가 끝나면 "만든 것 / 검증 숫자 / 다음 단계"만 보고하고 멈춘다.
6. 확실하지 않으면 만들지 말고 질문한다.
7. 도구 이름을 지어내지 않는다. 사용 가능한 도구를 먼저 확인한다.
8. 모듈은 기본 독립. 연결은 사용자 클릭 시에만 ModuleLink.
9. 실제 집행·과금·외부 호출은 하지 않는다.

[10단계 공식]
0. 문서 읽기 — PRD/디자인 계획안을 끝까지 읽고 ① 화면 ② 토큰 ③ 컴포넌트 ④ 금지 ⑤ 미정값 표로 뽑는다. 만들지 않는다.
1. 계획 — 단일 진실 확정 후 화면 명세, 토큰, 컴포넌트 인벤토리, 플로우, 금지표, 리뷰 체크리스트. 승인 전 화면 생성 금지.
2. 프로브 — 폰트(Pretendard/JetBrains Mono), 브라우저 뷰포트, 도구 목록 확인. 산출: 프로브 표.
3. 페이지 — 산출물 구조 확정 (Cover / Design System / Components / Screens / Handoff).
4. 토큰 — Primitives → Semantic → Spacing → Radius → Text Styles. 전부 변수화.
5. 기초 보드 — 브랜드 / 컬러 / 타이포 / 스페이싱 보드. 넘침 0.
6. 컴포넌트 — 계층형 이름, Auto Layout 대응, 변형·상태. 핵심 10개 우선. 높이 붕괴 0.
7. 화면 — S0 → S8 → S9 순서. 1440×900, 화면당 primary 1개, 넘침·겹침 0.
8. 상태·플로우 — 빈/로딩/성공/실패 + 명시적 링크 플로우 3~4개.
9. 검증 — 변수 바인딩, 넘침 0, primary 1개, 대비 4.5:1, 금지 규칙 위반 0.
10. 핸드오프 — 토큰 표, 컴포넌트 인벤토리, 구현 매핑, 열린 이슈.

[검증 규칙]
- 색: Variable 바인딩 여부.
- 프레임: 자식이 밖으로 나가지 않는지.
- 화면당 primary 1개.
- 이모지·보라→파랑 그라데이션·글래스모피즘·네온·카드 안 카드 금지.
- 서술문 80단어 초과 금지(메타 라벨:값은 예외), transition: all 금지.
- 숫자·시간·로그·타임코드는 Mono. 한국어 라벨, 번역투 금지.

[보고]
각 단계: 만든 것 / 검증 숫자 / 다음 단계.
막힌 것: "차단됨 + 사유 + 우회안".
보고 후 멈춘다. 내가 "계속"이라고 할 때만 다음 단계로 간다.

[첫 응답]
0단계만 수행하고 ① 화면 목록 ② 토큰 ③ 컴포넌트 ④ 금지 규칙 ⑤ 미정 값만 보고하고 멈춰라.
```

## 5. 사용 순서

1. **3-1 결정을 먼저 내린다** (단일 진실 확정).
2. 0단계 보고 → "계속" → 1단계 → ... 한 단계씩 승인.
3. Figma 연결이 생기면 `{{TOOL_MODE}}`만 `Figma MCP`로 바꾸고 나머지는 그대로 사용.
