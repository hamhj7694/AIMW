# DESIGN-PLAN v5 — 사용성 부록 (쉬운 사용 / 자연어 진입)

> 상태: **v4 작업기록장에 덧붙이는 사용성 부록**
> 기존 동결 문서(`DESIGN-PLAN.md` §3, `DESIGN-PLAN-v4.md`)는 수정하지 않는다.
> 이 문서는 제품 규칙을 바꾸지 않고 **사용자가 조작해야 하는 양을 줄이는 방법**만 정의한다.

## 1. 왜 추가하는가

사용자 요구: "기능을 쓰려면 조작이 너무 많다. 비전공자도 편하게 쓰게 해달라. 자연어 채팅을 주요 진입점으로 쓸 수 있으면 좋겠다. 영상은 전체/일부/프레임을 파트별로 선택·수정할 수 있게, 글도 전체 작성과 부분 선택(드래그·마크·셀) 수정 요청이 가능하게."

v4까지는 화면마다 전용 도구 어휘를 넣었지만, 여전히 사용자가 여러 컨트롤을 직접 찾아야 했다. v5는 **문장으로 요청 → 화면이 선택값을 미리 채워줌 → 사용자가 확인만 하는** 흐름을 기본 진입점으로 삼는다.

## 2. 핵심 원칙

1. **자연어가 주 진입점이다.** 상단에 항상 작업 요청 입력을 둔다.
2. **이동과 준비까지만 한다.** 도우미는 화면을 열고 선택 범위와 요청 문장을 채운다. 실제 생성·수정·집행·과금은 하지 않는다.
   - **예시 문장은 입력창에만 채운다.** 예시를 눌러도 즉시 전송·화면 이동하지 않는다. 사용자가 내용을 확인하고 `요청하기`를 눌러야 요청이 실행된다. 자동 실행은 통제성을 해치므로 금지한다.
3. **외부 AI 호출은 없다.** 현재 구현은 로컬 규칙 기반 파서다. 모델·API·토큰·전송을 약속하지 않는다.
4. **전체 챗봇 + 모듈별 문맥 요청을 함께 쓴다.** 어디서든 같은 도우미를 쓰되, 지금 보고 있는 모듈에 맞는 예시 문장을 함께 제공한다. 모듈마다 별도 봇을 만들지 않고 하나의 도우미가 문맥을 바꾼다.
5. **대화는 휘발성이다.** 현재 화면에만 남고 저장·전송·학습하지 않는다.
6. **기존 규칙은 그대로다.** 동의, 상한, 2차 확인, 권리 확인, 게이트, 공개 범위 수집은 그대로 유지한다.

## 3. 자연어 작업 도우미 (CommandDock)

### 3.1 배치

- 검은 헤더 바로 아래, 모듈 띠 위에 고정 배치한다. 어떤 모듈에 있어도 같은 위치에서 요청할 수 있다.
- 입력창 + `요청하기` 버튼 + 예시 문장 버튼으로 구성한다.
- 예시 문장을 누르면 **입력창에만 채워진다.** 입력 없이 바로 요청되지 않는다. 비전공자가 문장을 고민하지 않도록 하되, 최종 실행은 사용자가 `요청하기`를 눌러 결정한다.
- 요청 후에는 대화 서랍이 열려 요청 문장, 도우미 응답, "다시 열기" 동작을 보여준다.

### 3.2 모듈별 문맥

| 현재 모듈 | 도우미가 먼저 보여줄 예시 | 도우미가 여는 화면 |
|---|---|---|
| S0 | "공개 범위 자료 모아줘" | 수집함 |
| S1 | "비슷한 레퍼런스 정리해줘" | 레퍼런스 보드 |
| S2 | "첫 문단 다시 써줘" | 글쓰기 데스크 + 선택 구간 |
| S3 | "이 콘텐츠 드라이런 예약해줘" | 발행 스케줄러 |
| S4 | "지표 요약과 개선안 보여줘" | 성과 리포트 |
| S5 | "우리 자산 라이브러리 열어줘" | 콘텐츠 라이브러리 |
| S6 | "이동평균 예측 보여줘" | 예측 대시보드 |
| S7 | "관심군 세그먼트 만들어줘" | 세그먼트 빌더 |
| S8 | "영상 2초부터 4초까지 자막 고쳐줘" | 영상 워크벤치 + 구간 |
| S9 | "예산 10만원 시뮬레이션" | 검색 성장 콘솔 + 예산 탭 |

문맥은 화면 이동을 바꾸지 않는다. 어떤 모듈에서 요청해도 문장의 내용이 목적지를 결정한다.

### 3.3 요청 해석 규칙

| 문장 단서 | 열리는 화면 | 미리 채우는 값 |
|---|---|---|
| 영상 / 숏폼 / 콘티 / 샷 / 타임코드 / 자막 / 게이트 | S8 부분 수정 탭 | 범위, 초 단위 구간, `shot_id`, 요청 문장 |
| 글 / 문단 / 카피 / 브리프 / 맞춤법 / 다시 써 | S2 | 섹션(F4), 선택 범위, 요청 문장 |
| 발행 / 예약 / 게시 / 드라이런 | S3 | 없음 |
| 수집 / 공개 범위 / 키워드 등록 | S0 | 요청 문장 |
| 검색 / SEO / 예산 / 시뮬레이션 | S9 | 예산 탭 또는 진단 탭, 요청 문장 |
| 콘텐츠 / 자산 / 라이브러리 | S5 | 없음 |
| 세그먼트 / 오디언스 / 관심군 | S7 | 없음 |
| 예측 / 성과 / 신뢰도 | S6 | 없음 |
| 레퍼런스 / 경쟁사 / 유사도 | S1 | 없음 |
| 리포트 / 지표 / 개선안 | S4 | 없음 |
| 판단 불가 | S0 | 요청 문장 + 예시 안내 |

초가 두 개 있으면 시작·끝 구간으로, 하나면 그 시점 전후 2초로 해석한다. `SH-02` 형태의 샷 번호는 `shot_id`로 그대로 넘긴다.

## 4. 영상 부분 선택과 수정

- 범위는 세 가지다: **전체 영상 / 구간(씬) / 프레임(콘티)**.
- 전체 영상: 전체 타임코드를 검토 대상으로 남긴다. 자동 재생성 없음.
- 구간: 타임라인을 드래그해 시작·끝을 정한다. 시각적 선택과 `timecode` 문자열이 함께 기록된다.
- 프레임: 샷 스트립 또는 콘티 격자에서 한 장을 고른다. `shot_id`가 함께 기록된다.
- 수정 요청은 선택 범위와 요청 문장을 목록에 남긴다. 상태는 `검수 대기` 또는 `기록됨`이며 사람이 승인하기 전에는 반영되지 않는다.
- 자연어 요청으로 들어온 구간·샷 번호가 같은 선택 UI에 그대로 채워진다.
- 소스 모드 3종, 제작 모드 6종(기본 미선택), `rights_flag` / `rights_confirmed_by`, G1~G4 순차 승인은 변경하지 않는다.

## 5. 글 부분 선택과 수정

- 전체 원고는 계속 직접 편집할 수 있다.
- 부분 선택은 세 가지 방법을 지원한다: **드래그 선택 / 하이라이트(mark) 표시 / 줄 셀 선택**.
- 드래그 선택은 문자 시작·끝 위치를, 줄 셀은 줄 번호를 수정 대상으로 기록한다.
- 선택한 문장은 미리보기에 빨간 표시로 보이고, 요청 문장과 함께 수정 요청 목록에 추가된다.
- 자연어 요청이 들어오면 첫 문단·마지막 문단·선택 구간 중 하나를 미리 지정한 상태로 화면을 연다.
- 실제 텍스트 자동 생성은 하지 않는다. 요청은 기록이고 사람이 확인한다.

## 6. 지키는 제품 규칙 (변경 없음)

- 10개 독립 라우트, 기본 `연결 안 함`, 클릭 시에만 ModuleLink.
- Collector는 공개 범위만. 로그인·유료벽 우회, 스크래핑, 자동 호출 없음.
- S9는 4탭, `is_forecast=true`, 소유 계정, Google 1순위/네이버 2순위, 90일/12개월, 실제 집행 없음.
- 비용·입찰·예산 변경은 명시적 동의. 기본 상한 0원, 초과 시 실행 불가, 10만원 이상은 2차 확인.
- 시각 톤은 v4를 유지한다. 그라데이션·글래스·네온·이모지·카드 안 카드·끝 화살표 버튼 금지.

## 7. 검증 기준

- 빌드·린트 경고 0.
- 10라우트 콘솔 오류 0, 가로 오버플로 0, 금지 패턴 0.
- 자연어 예시 문장이 목적지 화면과 선택값을 여는지 확인.
- S8 범위 3종 전환, 타임라인 드래그, 프레임 선택, 수정 요청 기록 확인.
- S2 드래그·줄 셀·요청 범위 수정 기록 확인.
- 기존 S0/S8/S9 동작(수집·링크, 권한→G1 승인, 2차 확인) 회귀 없음.

> 최종 시각 판단은 사용자가 직접 화면을 확인해야 한다. 이 문서는 동결 기획 문서를 대체하지 않고 보완한다.
