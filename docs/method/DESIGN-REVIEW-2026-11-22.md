# 디자인 리뷰 — 2026-11-22 (사용자 2차 거절 이후)

`aimw-design-review` 스킬의 절차에 따라 코드와 계산된 스타일만 근거로 현재 화면을 비평했다. 이미지는 모델이 볼 수 없으므로 이미지에 대한 추측은 포함하지 않는다.

## 1. 3기둥 평가

| 기둥 | 평가 | 근거 |
|---|---|---|
| Frictionless | **메이저** | S0에 `수집`, `키워드 추가`, 4개 상태 전환 버튼, 5개 파트 탭, `S1에서 분석`이 함께 있음. 주 액션이 1개로 수렴하지 않음 |
| Quality Craft | **블로커** | 헤어라인 규칙 + 모노 마이크로 라벨 + 0 radius가 화면 전체 어휘. 이는 frontend-design 스킬이 "AI 디폴트"로 지목한 조합이다. v3에서 배지·박스를 걷어냈지만 어휘 자체는 유지 |
| Trustworthy | **통과** | 샘플·예측·권리·지출 상한 라벨이 데이터 옆에 남아 있음 |

## 2. 발견한 문제

1. **[블로커]** "라이트테이블"이라는 컨셉 자체가 브로드시트 헤어라인 디폴트였다. 토큰은 지켰지만 시각 문법이 여전히 생성형 UI의 전형이다.
2. **[메이저]** `.page-head__num`의 큰 `S0`는 numbered marker의 남용이다. 시퀀스가 아닌 화면 식별자에 큰 숫자를 쓰면 장식이 된다.
3. **[메이저]** S0 한 화면에 KPI 띠 · 등록 폼 · 3개 요약 패널 · 5개 탭 · 대장 목록 · 링크 패널이 공존한다. 계층은 있지만 "지금 뭘 해야 하는가"가 흐려진다.
4. **[메이저]** 10개 라우트가 모두 같은 골격을 그대로 재사용한다. 모듈별 성격(수집/승인/예산)이 구조에 반영되지 않았다.
5. **[마이너]** `샘플 데이터`, `성공`, `연동 대기` 같은 상태 주석이 여전히 화면 곳곳에 붙어 있다.

## 3. 제거해야 할 것 (추가하지 말 것)

- 큰 모듈 번호 장식
- 상태 배지 나열 (필요한 상태만 문장으로)
- 화면마다 반복되는 4칸 수치 띠
- 근거 없는 아이콘과 구획선
