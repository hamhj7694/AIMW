## 5. 열린 이슈

- Figma 파일은 여전히 미연결. `figma/components.svg`와 `figma/HANDOFF.md`로 수동 이관 가능.
- 기획 저장소의 `DESIGN-PLAN.md` §3은 변경하지 않음. 시각 토큰 단일 진실은 `DESIGN-PLAN-v2.md`.
- 기획 문서의 도메인 고정 예시 잔존은 기획 동결로 미수정. 앱 화면 카피에는 사용하지 않음.

## 6. v3 재설계 (사용자 지적 반영)

사용자가 v2 결과를 보고 "토큰만 바꾼 느낌, 여전히 AI 티"라고 지적했다. 리스킨이 아니라 구성 자체를 다시 설계했다.

| v2에서 남아 있던 문제 | v3 처리 |
|---|---|
| h1 24px, 나머지 10~13px로 위계가 없는 마이크로 라벨 벽 | h1 48px/700, 본문 15~16px, 라벨 11px로 위계 재편. 모노는 코드·수치·타임코드에만 사용 |
| 배지 13개, 아이콘 26개, 박스 패널 6개가 화면을 장식 | 배지는 밑줄 주석으로, 패널은 윤선 구획으로, 아이콘은 머리에서 제거 |
| KPI 4장의 동일한 카드 | 상하 눈금만 있는 수치 띠 |
| 카드 그리드가 반복되는 대시보드 레이아웃 | 번호가 붙은 대장 형태의 목록 (`F-01` 스타일 인덱스) |
| 10개 라우트가 모두 같은 템플릿 | 각 화면 머리에 큰 모듈 번호(S0~S9)를 배치한 작업지시서 톤 |
| 제목이 길고 설명적임 | "공개 범위 수집", "영상 워크벤치", "검색 성장"처럼 짧게 정리 |

토큰 10색과 금지 규칙(그라데이션·글래스·그림자·둥근 모서리·이모지·가운뎃점 메타·끝 화살표)은 그대로 유지했다. 제품 규칙과 인터랙션은 변경하지 않았다.

재검증: `npm run build` 통과, `npm run lint` 경고 0, 10라우트 콘솔 에러 0, 가로 오버플로 0, 금지 패턴 0. S0 수집·모듈 링크, S8 권리 다이얼로그, S9 예산 시뮬레이션 동작 확인.

> 한계: 현재 환경에서는 스크린샷 이미지를 모델이 직접 볼 수 없어 시각 판단은 계산된 스타일·구조·비율로 검증했다. 최종 미적 판단은 사용자가 화면을 직접 봐야 한다.

## 7. v4 전면 교체 (사용자 2차 거절 이후)

사용자가 "모든 디자인 스타일을 통째로 바꿔서 개선해야 한다"고 판단했다. 부분 수정이 아니라 `DESIGN-PLAN-v4.md`(작업기록장)로 시각 언어 전체를 교체했다.

| v3에서 제거한 것 | v4에서 넣은 것 |
|---|---|
| 좌측 코드 레일, 큰 `S0` 장식 숫자 | 상단 가로 모듈 띠, 활성 모듈 붉은 바탕 + 흰 글자 |
| 연한 종이 작업표 + 헤어라인 구획 | 검은 헤더와 검상 기록, 3px 굵은 선으로 구획 |
| 투명 수치 띠 | 검은 수치 띠 + 흰 모노 숫자, 상태는 7px 사각 도장 |
| 행마다 중복된 번호·샘플 배지 | 대장 번호(`01`, `02`…)와 짝수 행 띠, 배지 9개 이하로 축소 |
| 아이콘이 남은 버튼·카드 | 화면 아이콘 숨김, 의미는 글로 표현 |

토큰 10색을 `#EBEAE6 / #F7F6F2 / #101216 / #B03A28` 중심으로 교체했고 `aimw-design/tokens.css`를 v4 기준으로 갱신했다. 제품 규칙·인터랙션·데이터는 변경하지 않았다.

재검증: `npm run build` 통과(CSS 17.85 kB / JS 303.71 kB), `npm run lint` 경고 0, 10라우트 콘솔 에러 0·가로 오버플로 0, 그라데이션/글래스/그림자/이모지 0. 대비 실측 ink/paper 15.57, ink-2/paper 8.30, muted/sheet 5.05, mark/paper 5.01, sheet/ink 17.34, frame/mark 6.03. S0 수집·모듈 링크, S8 권리 확인→G1 승인(`approved_by: 검수자2`), S9 시뮬레이션 및 10만원 이상 2차 확인 동작 확인.

### 7.1 사용자 피드백 반영

사용자가 팔레트는 긍정하면서 표의 흰/회색 줄무늬와 일부 배치를 지적했다.

- 데이터 표와 대장 목록의 짝수 행 배경 제거. 구획은 2px 선으로만 유지.
- 820px 이하에서 모듈 띠를 가로 스크롤 대신 5×2 격자로 변경. 10개 모듈이 한 화면에 모두 보임(실측 밴드 높이 80px, 표시 모듈 10개).
- 좁은 화면에서 숨겼던 헤더의 제공자·예상비용 정보를 다시 표시(실측 4개 항목 전부 visible).
- S0·S9 입력 행을 균등 폭 그리드로 정리해 폼 배치 개선.
- 재검증: 빌드·린트 통과, 785px 가로 오버플로 0, 콘솔 에러 0, 줄무늬 규칙 0.

> 남은 한계: 브라우저 뷰포트가 785px라 820px 이상의 데스크톱 타이포그래피(42px 제목)는 코드와 계산값으로만 확인했다. 최종 시각 판단은 사용자가 직접 확인해야 한다.

## 8. v2 모듈 재구성 + v5 사용성 반영 (현재 구현)

사용자 요구 두 단계를 순서대로 반영했다.

1. "각 기능이 주력인 사이트처럼 보이되 톤은 맞춰야 한다" → v2 모듈별 전용 도구 화면.
2. "조작이 너무 많다, 비전공자도 쉽게, 자연어 채팅을 진입점으로" → v5 사용성 부록.

### 8.1 문서 먼저, 코드 나중

- 동결 기획 문서(`DESIGN-PLAN.md` §3, `DESIGN-PLAN-v4.md`)는 수정하지 않았다.
- 새 요구는 `aimw-design/DESIGN-PLAN-v5-EASE.md`에 먼저 기록했다.
- 문서 상태는 `aimw-design/CURRENT-STATUS.md`에 등록했다.
- 앱 기준 기록은 `aimw-app/DESIGN-V2.md`에, README는 현재 구현 범위로 갱신했다.

### 8.3 지킨 규칙

- 도우미는 화면 이동과 선택값 준비만 한다. 생성·수정·집행·과금 없음.

- 예시 클릭은 입력만 채운다. 사용자가 `요청하기`를 눌러야 실행된다.
- S8 권리 확인과 G1~G4, S9 4탭·`is_forecast`·상한 0원·2차 확인은 변경 없음.
